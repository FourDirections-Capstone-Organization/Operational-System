## 2. Critical Discovery — GUID Mismatch

The CSV GUIDs **do not match** the GUIDs in the target database:

| Entity | CSV GUID example | DB GUID example |
|--------|-----------------|-----------------|
| ENC001 | `2aacc0aa-9c94-4308-95ac-7d96ce817ad9` | `a5019350-1472-4a29-9519-97e82083cf3a` |
| MGR001 | `0fb1eb66-bad8-4bf3-92b0-2f9e0095218b` | `92177b16-506e-46ce-ad22-d8948a4588b9` |
| Departments | `1d9b6bf9-...`, `45453926-...`, `b6476aff-...`, `a7946704-...` | All 4 differ (e.g., `de865b4e-...`) |

**Consequences:**
- All 9 users already existed in the DB (by EmployeeNumber) with different GUIDs → user inserts skipped entirely
- Assignments/recommendations reference CSV user GUIDs → **FK violations** unless remapped
- Tasks reference `CreatedById` (MGR001) and `AssignedDepartmentId` → needed the DB MGR001 GUID and CSV department GUIDs to exist

---

## 3. Import Strategy

1. **Departments** — Insert the 4 CSV-referenced departments with their CSV GUIDs (names via mapping: Last Mile, Dispatch, Logistics, Forwarding and Delivery). `ON CONFLICT ("Id") DO NOTHING`.
2. **Users** — Skip entirely (already exist locally). Build remap table: `CSV user GUID → DB user GUID` (matched by EmployeeNumber).
3. **Tasks** — Insert all 299 with `CreatedById` = **DB MGR001 GUID** (`92177b16-506e-46ce-ad22-d8948a4588b9`), `AssignedDepartmentId` = CSV GUID, `AssignmentScope` = 1 (Team) if `has_multiple_assignments=1` else 0 (SingleEmployee). `ON CONFLICT ("Id") DO NOTHING`.
4. **TaskAssignments** — Insert 439 with `AssignedUserId` **remapped** to DB user GUID. Skip rows whose task/user GUID is missing.
5. **Recommendations** — Insert 65 with `AssigneeId`/`CoordinatorId` **remapped**. Skip rows with missing dependencies.

**Delivery method:** SQL generated by a PowerShell script, piped **inside the container**:
```
Get-Content import.sql -Raw | docker compose exec -T db psql -U postgres -d backend_db --set ON_ERROR_STOP=1
```
This avoids the host-port-5432 conflict (a local PostgreSQL service shadows Docker's port mapping on this machine — verified: two listeners on 5432, PIDs 5652 + 10308).

## 4. Bugs Hit & Fixed During Import

| # | Error | Root cause | Fix |
|---|-------|-----------|-----|
| 1 | Script stopped on docker stderr | `$ErrorActionPreference = "Stop"` + native stderr in PS 5.1 | Set `"Continue"`, filter output with `Where-Object { $_ -is [string] }` |
| 2 | `return if (...)` command not found | PS7-only expression syntax used in PS 5.1 (`QBool` helper) | Rewrote with explicit `if/return` statements |
| 3 | `null value in column "IsConfidential" of relation "Tasks"` | Task model has NOT NULL `IsConfidential` with **no DB default** (EF Core doesn't emit defaults for C# initializers); INSERT omitted it | Added `IsConfidential = FALSE` to the task INSERT |
| 4 | psql errors invisible | `2>&1` stderr lines become ErrorRecords, filtered out by string check | Inspect full output via `2>&1 | Select-String "ERROR"` outside the script filter |

The first two failed runs were **fully rolled back** (single `BEGIN; ... COMMIT;` transaction + `ON_ERROR_STOP=1`), so no partial data was ever committed.

## 6. Reproducing on Another Machine

The importer tool/script was **removed by request** — there is no committed tool. To reproduce:

1. Ensure Docker is up and the backend has run migrations (tables exist).
2. Determine the target DB's user GUIDs (they will differ per machine):
   ```
   SELECT "EmployeeNumber", "Id" FROM "Users";
   ```
3. Generate SQL with these rules:
   - Skip users whose EmployeeNumber exists
   - Remap CSV user GUID → local user GUID for assignments/recommendations
   - Tasks: `CreatedById` = local MGR001 GUID; include `IsConfidential FALSE`; `AssignmentScope` from `has_multiple_assignments`
   - Departments: insert CSV-referenced GUIDs (name mapping in report section 3)
   - Wrap in `BEGIN; ... COMMIT;` with `ON CONFLICT ("Id") DO NOTHING`
4. Pipe into the container (never host port 5432 if a local Postgres exists):
   ```
   Get-Content import.sql -Raw | docker compose exec -T db psql -U postgres -d backend_db --set ON_ERROR_STOP=1
   ```

**Key gotchas for other systems:**
- GUIDs in the CSVs are NOT portable — always remap by EmployeeNumber
- `Tasks.IsConfidential` has no DB default → must be provided
- Use `docker compose exec -T db psql` (container network) to avoid host port conflicts
- Keep everything in one transaction so failures roll back cleanly
