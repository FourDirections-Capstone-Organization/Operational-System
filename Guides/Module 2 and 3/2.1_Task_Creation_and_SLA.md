# Sub-Module 2.1: Task Creation & SLA

## Functional Requirements Covered

| FR ID | Requirement Name | Description | Priority |
|-------|------------------|-------------|----------|
| FR-010 | Assigned Task Visibility | The system shall restrict task visibility so that Encoders, Dispatchers, and Couriers/Drivers can only view tasks explicitly assigned to them or their department. | High |
| FR-011 | Coordinator Management Scoping | The system shall allow Coordinators to view, create, assign, and manage tasks within their assigned department. | Medium |
| FR-012 | Manager Dashboard Access | The system shall allow the Manager full write and view access over all tasks, users, and audit logs. | Medium |
| FR-013 | Confidential Task Visibility | The system shall allow Coordinators to flag specific tasks as confidential, restricting visibility exclusively to Coordinators and the Manager. | Low |
| FR-017 | Task Form Configuration | The system shall allow Coordinators to create tasks with title, description, priority level, deadline, and assign to user(s)/department. | High |
| FR-018 | Document Memo Attachments | The system shall allow Coordinators to attach documents (PDF, DOCX, XLSX, JPG, PNG; max 20MB) to task profiles. | High |
| FR-019 | Destination Scoping | The system shall allow Coordinators to assign tasks to a Single Employee, Team, or Department. | High |
| FR-020 | Priority & Urgency Classification | Every task shall be classified as Routine Daily Task or Special Task, independent of Priority Level. | High |
| FR-021 | Urgent SLA Enforcement | Tasks with Priority = Urgent shall auto-receive a deadline of exactly 24 hours from creation, overriding any manual entry. | High |

## 1. High-Level Pseudocode

### What We're Building

We need to create a system where:
1. Coordinators can create tasks with all required information (title, description, priority, deadline, assignee)
2. Coordinators can attach files to tasks (PDF, DOCX, XLSX, JPG, PNG up to 20MB)
3. Tasks can be assigned to a Single Employee, an entire Team, or a whole Department
4. Every task has a Classification (Routine Daily Task or Special Task) separate from its Priority
5. When a task is marked as Urgent, the system automatically locks the deadline to exactly 24 hours from creation
6. Tasks can be marked as Confidential (only visible to Coordinators and Managers)
7. Task visibility is filtered based on user role (Manager sees all, Coordinator sees department tasks, others see only assigned)

### Step-by-Step Logic

```
STEP 1: Create Enums (the "labels" we use to categorize things)
├── TaskStatus → NotStarted, InProgress, DonePendingReview, Completed, OnHold, Cancelled

├── Status (enum from Step 1, default = NotStarted)

STEP 5: Create DTOs (Data Transfer Objects - the "forms" for sending/receiving data)
```

## 2. High-Level Explanation of Concepts

### Concept 1: Enums (What it is)

**Enums (Enumerations)** are a way to define a variable that can only be one of a fixed set of named values. Think of it like a dropdown menu with pre-defined options.

**Why we use it:**
- Prevents invalid values (you can't set Priority to "SuperDuperHigh" - it must be Low, Medium, High, or Urgent)
- Makes code readable (`task.Priority == PriorityLevel.Urgent` is clearer than `task.Priority == 3`)
- Database stores them as integers (efficient) but code uses readable names

**How it works:**
```
// Define the enum (the list of options)
enum PriorityLevel {
    Low = 0,
    Medium = 1,
    High = 2,
    Urgent = 3
}

// Use it
task.Priority = PriorityLevel.Urgent;  // Clear and readable

// In the database, it's stored as the number 3
// But in our code, we see "Urgent"
```

**Alternatives:**
- **String constants**: Store "Low", "Medium" as text. Works but takes more space and allows typos.
- **Magic numbers**: Use 0, 1, 2, 3 directly. Confusing - what does 3 mean?
- **Lookup table**: Store options in a database table. Overkill for fixed options.

**Common Mistakes:**
- Forgetting to add new enum values when requirements change
- Not handling all enum values in switch statements
- Changing enum order (changes database values)

### Concept 2: File Upload with IFormFile (What it is)

**IFormFile** is ASP.NET Core's built-in way to handle file uploads from HTTP requests. When a user uploads a file through a form, ASP.NET Core wraps it in an `IFormFile` object.

**Why we use it:**
- Built into ASP.NET Core (no external packages needed)
- Handles multipart form data automatically
- Provides file metadata (name, size, content type)
- Gives us a stream to read the file content

**How it works:**
```
1. User selects a file in their browser and clicks "Upload"
2. Browser sends the file as multipart/form-data
3. ASP.NET Core receives it and creates an IFormFile object
4. We check: Is the file type allowed? Is the size under 20MB?
5. We save the file to disk (uploads/ folder)
6. We save the file path in the database (TaskAttachment record)
```

**Alternatives:**
- **Cloud storage (AWS S3, Azure Blob)**: Good for production but adds complexity and cost
- **Base64 encoding**: Convert file to text and store in database. Bad for large files.
- **Database binary storage**: Store file bytes directly in database. Makes database huge.

**Common Mistakes:**
- Not validating file types (someone could upload an .exe file)
- Not limiting file size (someone could upload a 1GB file)
- Storing files with original names (could overwrite each other or have special characters)
- Not handling upload failures (what if disk is full?)

### Concept 3: SLA Enforcement (What it is)

**SLA (Service Level Agreement)** is a承诺 (promise) about how quickly something will be done. In our case, an "Urgent" task must be completed within 24 hours.

**Why we use it:**
- Business requirement: urgent tasks need fast turnaround
- Automatic enforcement removes human error (Coordinator can't forget to set the deadline)
- Creates accountability (everyone knows urgent = 24 hours)

**How it works:**
```
1. Coordinator creates a task and sets Priority = Urgent
2. System detects: "Oh, this is Urgent!"
3. System calculates: Deadline = Now + 24 hours
4. System IGNORES any deadline the Coordinator typed in
5. System locks the deadline (IsSLALocked = true)
6. Nobody can change the deadline after this

Example:
- Task created at: 2024-01-15 10:00 AM
- Priority: Urgent
- System sets deadline to: 2024-01-16 10:00 AM (exactly 24 hours later)
- Even if Coordinator typed "2024-01-20", the system overrides it
```

**Alternatives:**
- **Manual deadline**: Let Coordinator set any deadline. Risk: they might set it too far away.
- **Configurable SLA per priority**: Different time limits for each priority. More flexible but more complex.
- **Warning only**: Just warn the Coordinator but let them override. Doesn't enforce the rule.

**Common Mistakes:**
- Not locking the deadline after auto-setting (Coordinator could change it back)
- Using business hours instead of 24 hours (requirement says exactly 24 hours)
- Not recording the enforced deadline in the audit log

### Concept 4: Assignment Scoping (What it is)

**Assignment Scoping** means choosing HOW broadly to assign a task: to one specific person, to a team of people, or to an entire department.

**Why we use it:**
- Flexibility: sometimes you know exactly who should do it, sometimes you just need "someone from Dispatch"
- Efficiency: Coordinators don't always need to pick individual people
- Visibility: tasks assigned to a department are visible to all members of that department

**How it works:**
```
Three options:

1. SingleEmployee:
   - Coordinator picks one specific person
   - Only that person sees the task in "My Tasks"
   - Example: "John Doe (Employee #0005)"

2. Team:
   - Coordinator picks a group of people
   - All team members see the task
   - Example: "Morning Shift Team" (5 people)

3. Department:
   - Coordinator picks an entire department
   - ALL members of that department see the task
   - Example: "Dispatch Team" (everyone in that department)

Implementation:
- Task record stores: AssignmentScope + the target (UserId, list of UserIds, or DepartmentId)
- TaskAssignment table links tasks to individual users
- When scope = Department, we create TaskAssignment records for ALL active users in that department
```

**Alternatives:**
- **Always assign to individuals**: Simpler but requires Coordinator to know every employee
- **Role-based assignment**: Assign to "any Dispatcher". Too vague.
- **Round-robin**: Auto-assign to next available person. Doesn't fit the requirements.

**Common Mistakes:**
- Not checking if assigned users are active (could assign to deactivated users)
- Not creating TaskAssignment records for department/team assignments
- Not updating assignments when users are transferred to different departments

### Concept 5: Task Classification vs Priority Level (What it is)

**Task Classification** (Routine Daily Task vs Special Task) describes the NATURE of the task.
**Priority Level** (Low, Medium, High, Urgent) describes the URGENCY of the task.

These are TWO SEPARATE concepts that are independent of each other.

**Why they're separate:**
- A routine task can be urgent (e.g., daily report but needed ASAP)
- A special task can be low priority (e.g., one-time project with no rush)
- Business needs both dimensions to organize work properly

**How it works:**
```
Classification (WHAT kind of task):
├── RoutineDailyTask → Regular, recurring, expected work
└── SpecialTask → One-time, unusual, project-based work

PriorityLevel (HOW urgent):
├── Low → No rush
├── Medium → Normal timeline
├── High → Important, needs attention
└── Urgent → Must be done in 24 hours (SLA enforced)

Examples:
- "Daily parcel sorting" = Routine + Medium priority
- "Monthly inventory audit" = Routine + High priority
- "Fix broken conveyor belt" = Special + Urgent priority
- "Organize office party" = Special + Low priority
```

**Common Mistakes:**
- Mixing up classification and priority (they're NOT the same thing)
- Making classification affect the SLA (only Priority = Urgent triggers SLA)
- Not allowing filtering by both independently

### Concept 6: Task Visibility Filtering (What it is)

**Task Visibility Filtering** controls WHICH tasks a user can see based on their role. This is a security feature that ensures users only access tasks they're authorized to view.

**Why we use it:**
- Security: prevents unauthorized access to sensitive tasks
- Privacy: confidential tasks are only visible to Coordinators and Managers
- Relevance: employees only see tasks assigned to them (less clutter)
- Compliance: meets FR-010, FR-011, FR-012, FR-013 requirements

**How it works:**
```
VISIBILITY RULES BY ROLE:

1. Manager:
   → Sees ALL tasks (no filter)
   → Can see confidential tasks
   → Full dashboard access (FR-012)

2. Coordinator:
   → Sees tasks in their department (FR-011)
   → Can see confidential tasks (FR-013)
   → Can create, assign, and manage tasks

3. Dispatcher/Encoder/Courier:
   → Sees ONLY tasks assigned to them (FR-010)
   → CANNOT see confidential tasks (FR-013)
   → Can only update their assigned tasks

CONFIDENTIAL TASKS (FR-013):
- Coordinators can mark tasks as confidential (IsConfidential = true)
- Confidential tasks are ONLY visible to Coordinators and Managers
- Regular employees (Dispatcher/Encoder/Courier) cannot see them at all

EXAMPLE:
Task list for different roles:
- Manager (100 tasks total): Sees all 100 tasks (including 5 confidential)
- Coordinator (same department): Sees 40 tasks in their department (including 5 confidential)
- Encoder (assigned to 3 tasks): Sees only 3 tasks (none confidential)

IMPLEMENTATION:
1. Get user's role from JWT token
2. Get user's department ID (for Coordinators)
3. Apply filter based on role:
   - Manager: no filter
   - Coordinator: WHERE DepartmentId = user.DepartmentId
   - Others: WHERE AssignedUserId = user.Id (via TaskAssignment)
4. For non-Manager/Coordinator: ADD filter WHERE IsConfidential = false
```

**Alternatives:**
- **No filtering**: Everyone sees everything. Security risk.
- **Permission-based**: More granular but complex to implement and maintain.
- **Separate endpoints per role**: More code duplication.

**Common Mistakes:**
- Forgetting to filter confidential tasks for regular employees
- Not checking department for Coordinators (they should only see their department's tasks)
- Filtering at the application level instead of database level (performance issue)
- Not passing user context (role, department) to the service layer

**File: `backend/Modules/TaskManagement/TaskService.cs`**

```csharp
using Microsoft.EntityFrameworkCore;
using Backend.Data;
using Backend.Models;
using Backend.Models.DTOs;
using Backend.Models.Enums;

namespace Backend.Modules.TaskManagement;

public class TaskService : ITaskService
{
    private readonly AppDbContext _db;

    public TaskService(AppDbContext db)
    {
        _db = db;
    }

    public async Task<ApiResponseDTO<TaskResponseDTO>> CreateAsync(CreateTaskDTO dto, Guid creatorId)
    {
        var creator = await _db.Users.FindAsync(creatorId);
        if (creator is null)
            return ApiResponseDTO<TaskResponseDTO>.Failure("Creator not found");

        if (creator.Role != UserRole.Coordinator && creator.Role != UserRole.Manager)
            return ApiResponseDTO<TaskResponseDTO>.Failure("Only Coordinators and Managers can create tasks");

        if (string.IsNullOrWhiteSpace(dto.Title))
            return ApiResponseDTO<TaskResponseDTO>.Failure("Task title is required");

        if (string.IsNullOrWhiteSpace(dto.Description))
            return ApiResponseDTO<TaskResponseDTO>.Failure("Task description is required");

        var now = DateTime.UtcNow;
        var deadline = dto.Deadline;
        var isSLALocked = false;

        if (dto.PriorityLevel == PriorityLevel.Urgent)
        {
            deadline = now.AddHours(24);
            isSLALocked = true;
        }
        else
        {
            if (!deadline.HasValue)
                return ApiResponseDTO<TaskResponseDTO>.Failure("Deadline is required for non-Urgent tasks");

            if (deadline.Value <= now)
                return ApiResponseDTO<TaskResponseDTO>.Failure("Deadline must be a future date/time");
        }

        var assignmentValidation = await ValidateAssignmentAsync(
            dto.AssignmentScope, dto.AssignedUserIds, dto.AssignedDepartmentId);

        if (!assignmentValidation.IsValid)
            return ApiResponseDTO<TaskResponseDTO>.Failure(assignmentValidation.ErrorMessage!);

        var task = new Task
        {
            Title = dto.Title.Trim(),
            Description = dto.Description.Trim(),
            PriorityLevel = dto.PriorityLevel,
            Classification = dto.Classification,
            Status = TaskStatus.NotStarted,
            AssignmentScope = dto.AssignmentScope,
            Deadline = deadline.Value,
            IsSLALocked = isSLALocked,
            IsConfidential = dto.IsConfidential,
            CreatedById = creatorId,
            AssignedDepartmentId = dto.AssignedDepartmentId,
            CreatedAt = now
        };

        _db.Tasks.Add(task);
        await _db.SaveChangesAsync();

        var assignedUserIds = await ResolveAssignedUserIdsAsync(
            dto.AssignmentScope, dto.AssignedUserIds, dto.AssignedDepartmentId);

        foreach (var userId in assignedUserIds)
        {
            _db.TaskAssignments.Add(new TaskAssignment
            {
                TaskId = task.Id,
                AssignedUserId = userId,
                AssignedAt = now
            });
        }

        await _db.SaveChangesAsync();

        return ApiResponseDTO<TaskResponseDTO>.Success(
            await MapToResponseDTOAsync(task),
            "Task created and assigned successfully");
    }

    public async Task<ApiResponseDTO<List<TaskResponseDTO>>> GetAllAsync(
        Guid requestUserId,
        UserRole requestUserRole,
        Guid? requestUserDepartmentId,
        TaskStatus? status = null,
        PriorityLevel? priority = null,
        TaskClassification? classification = null,
        Guid? assignedToUserId = null,
        Guid? departmentId = null,
        string? search = null)
    {
        var query = _db.Tasks
            .Include(t => t.CreatedBy)
            .Include(t => t.AssignedDepartment)
            .Include(t => t.Assignments)
                .ThenInclude(a => a.AssignedUser)
            .Include(t => t.Attachments)
            .AsQueryable();

        // === TASK VISIBILITY FILTER (FR-010, FR-011, FR-012, FR-013) ===
        switch (requestUserRole)
        {
            case UserRole.Manager:
                break;

            case UserRole.Coordinator:
                if (requestUserDepartmentId.HasValue)
                    query = query.Where(t => t.AssignedDepartmentId == requestUserDepartmentId.Value);
                break;

            case UserRole.Dispatcher:
            case UserRole.Encoder:
            case UserRole.Courier:
                query = query.Where(t => t.Assignments.Any(a => a.AssignedUserId == requestUserId));
                query = query.Where(t => !t.IsConfidential);
                break;
        }

        if (status.HasValue)
            query = query.Where(t => t.Status == status.Value);

        if (priority.HasValue)
            query = query.Where(t => t.PriorityLevel == priority.Value);

        if (classification.HasValue)
            query = query.Where(t => t.Classification == classification.Value);

        if (assignedToUserId.HasValue)
            query = query.Where(t => t.Assignments.Any(a => a.AssignedUserId == assignedToUserId.Value));

        if (departmentId.HasValue)
            query = query.Where(t => t.AssignedDepartmentId == departmentId.Value);

        if (!string.IsNullOrWhiteSpace(search))
        {
            var searchLower = search.ToLower();
            query = query.Where(t =>
                t.Title.ToLower().Contains(searchLower) ||
                t.Description.ToLower().Contains(searchLower));
        }

        var tasks = await query
            .OrderByDescending(t => t.CreatedAt)
            .ToListAsync();

        var response = new List<TaskResponseDTO>();
        foreach (var task in tasks)
        {
            response.Add(await MapToResponseDTOAsync(task));
        }

        return ApiResponseDTO<List<TaskResponseDTO>>.Success(response);
    }

    public async Task<ApiResponseDTO<TaskResponseDTO>> GetByIdAsync(Guid id, Guid requestUserId, UserRole requestUserRole)

    public async Task<ApiResponseDTO<TaskResponseDTO>> UpdateAsync(Guid id, UpdateTaskDTO dto, Guid requestUserId)
    {
        var task = await _db.Tasks
            .Include(t => t.Assignments)
            .Include(t => t.CreatedBy)
            .Include(t => t.AssignedDepartment)
            .FirstOrDefaultAsync(t => t.Id == id);

        if (task is null)
            return ApiResponseDTO<TaskResponseDTO>.Failure("Task not found");

        var requestUser = await _db.Users.FindAsync(requestUserId);
        if (requestUser is null || (requestUser.Role != UserRole.Coordinator && requestUser.Role != UserRole.Manager))
            return ApiResponseDTO<TaskResponseDTO>.Failure("Only Coordinators and Managers can update tasks");

        if (task.Status == TaskStatus.Completed)
            return ApiResponseDTO<TaskResponseDTO>.Failure("Cannot modify a completed task");

        if (task.Status == TaskStatus.Cancelled)
            return ApiResponseDTO<TaskResponseDTO>.Failure("Cannot modify a cancelled task");

        if (!string.IsNullOrWhiteSpace(dto.Title))
            task.Title = dto.Title.Trim();

        if (!string.IsNullOrWhiteSpace(dto.Description))
            task.Description = dto.Description.Trim();

        if (dto.PriorityLevel.HasValue)
        {
            task.PriorityLevel = dto.PriorityLevel.Value;

            if (dto.PriorityLevel.Value == PriorityLevel.Urgent)
            {
                task.Deadline = task.CreatedAt.AddHours(24);
                task.IsSLALocked = true;
            }
            else
            {
                task.IsSLALocked = false;
            }
        }

        if (dto.Classification.HasValue)
            task.Classification = dto.Classification.Value;

        if (dto.Deadline.HasValue && !task.IsSLALocked)
        {
            if (dto.Deadline.Value <= DateTime.UtcNow)
                return ApiResponseDTO<TaskResponseDTO>.Failure("Deadline must be a future date/time");

            task.Deadline = dto.Deadline.Value;
        }

        if (dto.AssignmentScope.HasValue)
            task.AssignmentScope = dto.AssignmentScope.Value;

        if (dto.AssignedDepartmentId.HasValue)
            task.AssignedDepartmentId = dto.AssignedDepartmentId;

        if (dto.IsConfidential.HasValue)
            task.IsConfidential = dto.IsConfidential.Value;

        if (dto.AssignedUserIds != null)
        {
            _db.TaskAssignments.RemoveRange(task.Assignments);

            foreach (var userId in dto.AssignedUserIds)
            {
                _db.TaskAssignments.Add(new TaskAssignment
                {
                    TaskId = task.Id,
                    AssignedUserId = userId,
                    AssignedAt = DateTime.UtcNow
                });
            }
        }

        task.UpdatedAt = DateTime.UtcNow;
        await _db.SaveChangesAsync();

        return ApiResponseDTO<TaskResponseDTO>.Success(
            await MapToResponseDTOAsync(task),
            "Task updated successfully");
    }

    private async Task<(bool IsValid, string? ErrorMessage)> ValidateAssignmentAsync(
        AssignmentScope scope, List<Guid>? userIds, Guid? departmentId)
    {
        switch (scope)
        {
            case AssignmentScope.SingleEmployee:
                if (userIds is null || userIds.Count == 0)
                    return (false, "At least one assigned user is required for SingleEmployee scope");

                if (userIds.Count != 1)
                    return (false, "Exactly one user must be assigned for SingleEmployee scope");

                var userExists = await _db.Users
                    .AnyAsync(u => u.Id == userIds[0] && u.IsActive && !u.IsDeactivated);

                if (!userExists)
                    return (false, "Selected user is inactive or does not exist");

                var userRole = await _db.Users
                    .Where(u => u.Id == userIds[0])
                    .Select(u => u.Role)
                    .FirstOrDefaultAsync();

                var allowedRoles = new[] { UserRole.Dispatcher, UserRole.Encoder, UserRole.Courier };
                if (!allowedRoles.Contains(userRole))
                    return (false, "Assigned user must be an active Dispatcher, Encoder, or Courier");

                return (true, null);

            case AssignmentScope.Team:
                if (userIds is null || userIds.Count == 0)
                    return (false, "At least one team member is required for Team scope");

                foreach (var userId in userIds)
                {
                    var exists = await _db.Users
                        .AnyAsync(u => u.Id == userId && u.IsActive && !u.IsDeactivated);

                    if (!exists)
                        return (false, $"User {userId} is inactive or does not exist");
                }

                return (true, null);

            case AssignmentScope.Department:
                if (!departmentId.HasValue)
                    return (false, "Department is required for Department scope");

                var deptExists = await _db.Departments
                    .AnyAsync(d => d.Id == departmentId.Value && d.IsActive);

                if (!deptExists)
                    return (false, "Selected department is inactive or does not exist");

                return (true, null);

            default:
                return (false, "Invalid assignment scope");
        }
    }

    private async Task<List<Guid>> ResolveAssignedUserIdsAsync(
        AssignmentScope scope, List<Guid>? userIds, Guid? departmentId)
    {
        switch (scope)
        {
            case AssignmentScope.SingleEmployee:
            case AssignmentScope.Team:
                return userIds ?? new List<Guid>();

            case AssignmentScope.Department:
                if (!departmentId.HasValue)
                    return new List<Guid>();

                return await _db.Users
                    .Where(u => u.DepartmentId == departmentId.Value
                        && u.IsActive
                        && !u.IsDeactivated)
                    .Select(u => u.Id)
                    .ToListAsync();

            default:
                return new List<Guid>();
        }
    }

    private async Task<TaskResponseDTO> MapToResponseDTOAsync(Task task)
    {
        await _db.Entry(task).Reference(t => t.CreatedBy).LoadAsync();
        await _db.Entry(task).Reference(t => t.AssignedDepartment).LoadAsync();
        await _db.Entry(task).Collection(t => t.Assignments).LoadAsync();

        foreach (var assignment in task.Assignments)
        {
            await _db.Entry(assignment).Reference(a => a.AssignedUser).LoadAsync();
        }

        return new TaskResponseDTO
        {
            Id = task.Id,
            Title = task.Title,
            Description = task.Description,
            PriorityLevel = task.PriorityLevel,
            Classification = task.Classification,
            Status = task.Status,
            AssignmentScope = task.AssignmentScope,
            Deadline = task.Deadline,
            IsSLALocked = task.IsSLALocked,
            IsConfidential = task.IsConfidential,
            CreatedById = task.CreatedById,
            CreatedByName = task.CreatedBy is not null
                ? $"{task.CreatedBy.FirstName} {task.CreatedBy.LastName}".Trim()
                : null,
            AssignedDepartmentId = task.AssignedDepartmentId,
            AssignedDepartmentName = task.AssignedDepartment?.Name,
            Assignees = task.Assignments.Select(a => new TaskAssigneeDTO
            {
                UserId = a.AssignedUserId,
                FullName = a.AssignedUser is not null
                    ? $"{a.AssignedUser.FirstName} {a.AssignedUser.MiddleName} {a.AssignedUser.LastName} {a.AssignedUser.Suffix}"
                        .Replace("  ", " ").Trim()
                    : "Unknown",
                EmployeeNumber = a.AssignedUser?.EmployeeNumber ?? "",
                Role = a.AssignedUser?.Role.ToString()
            }).ToList(),
            AttachmentCount = task.Attachments?.Count ?? 0,
            CreatedAt = task.CreatedAt,
            UpdatedAt = task.UpdatedAt
        };
    }
```

```csharp
    public async Task<ApiResponseDTO<TaskAttachmentResponseDTO>> UploadAsync(
        Guid taskId, IFormFile file, string? description, Guid uploaderId)
    {
        var taskExists = await _db.Tasks.AnyAsync(t => t.Id == taskId);
        if (!taskExists)
            return ApiResponseDTO<TaskAttachmentResponseDTO>.Failure("Task not found");

        var validation = ValidateFile(file);
        if (!validation.IsValid)
            return ApiResponseDTO<TaskAttachmentResponseDTO>.Failure(validation.ErrorMessage!);

        var uploadDir = Path.Combine(Directory.GetCurrentDirectory(), _fileSettings.UploadPath, taskId.ToString());

        if (!Directory.Exists(uploadDir))
            Directory.CreateDirectory(uploadDir);

        var uniqueFileName = $"{Guid.NewGuid()}{Path.GetExtension(file.FileName)}";
        var filePath = Path.Combine(uploadDir, uniqueFileName);

        using (var stream = new FileStream(filePath, FileMode.Create))
        {
            await file.CopyToAsync(stream);
        }

        var attachment = new TaskAttachment
        {
            TaskId = taskId,
            FileName = file.FileName,
            FilePath = filePath,
            FileSize = file.Length,
            FileType = Path.GetExtension(file.FileName).ToLower(),
            Description = description?.Trim(),
            UploadedById = uploaderId,
            CreatedAt = DateTime.UtcNow
        };

        _db.TaskAttachments.Add(attachment);
        await _db.SaveChangesAsync();

        await _db.Entry(attachment).Reference(a => a.UploadedBy).LoadAsync();

        var response = MapToResponseDTO(attachment);
        return ApiResponseDTO<TaskAttachmentResponseDTO>.Success(response, "Attachment uploaded successfully");
    }

    {
        var attachment = await _db.TaskAttachments.FindAsync(id);
        if (attachment is null)
            return ApiResponseDTO<bool>.Failure("Attachment not found");

        try
        {
            if (File.Exists(attachment.FilePath))
                File.Delete(attachment.FilePath);
        }
        catch (Exception ex)
        {
            _logger.LogWarning(ex, "Failed to delete file at {FilePath}", attachment.FilePath);
        }

        _db.TaskAttachments.Remove(attachment);
        await _db.SaveChangesAsync();

        return ApiResponseDTO<bool>.Success(true, "Attachment deleted successfully");
    }

    private (bool IsValid, string? ErrorMessage) ValidateFile(IFormFile file)

        if (file.Length > _fileSettings.MaxFileSizeBytes)
            return (false, $"File exceeds the maximum allowed size ({_fileSettings.MaxFileSizeBytes / 1024 / 1024}MB)");

        return (true, null);
    }
```
