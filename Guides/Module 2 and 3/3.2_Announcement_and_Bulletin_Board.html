1. Overview

The Announcement & Bulletin Board feature allows Coordinators and Managers to publish announcements visible to targeted user roles. All users can view, acknowledge, and comment on announcements targeted to them. The UI follows a Google Classroom-style card layout with a purple accent border.

6. Frontend Component — AnnouncementsTab.tsx

The component is located at frontend/src/components/AnnouncementsTab/AnnouncementsTab.tsx and is rendered in the SystemAdmin_Dashboard (Manager) via the announcements nav tab. It can also be added to OpAdmin_Dashboard (Coordinator) and OpEmployee_Dashboard (Employee) by importing and rendering with the appropriate canCreate prop.

UI States per Announcement Card

  • Header: Purple left border, gradient background, title, author, effective date, expiry badge, target audience badge
  • Content: Wrapped in a bordered card with white-space: pre-wrap
  • Acknowledge: Button with count badge; green when acknowledged; disabled after acknowledgment
  • Comment count: Displayed next to acknowledge button
  • Acknowledgments list: Collapsible <details> showing who acknowledged and when
  • Comments thread: Oldest-first with avatar (initials), name, timestamp, content
  • Comment input: Text field + send button (Enter key to send)

8. Service Flow

Creating an Announcement

Coordinator/Manager → POST /api/Announcement
→ AnnouncementController.Create() validates user role
→ AnnouncementService.CreateAsync():
  1. Validates expiry ≥ effective date
  2. Creates Announcement entity, saves to DB
  3. Resolves target user IDs via GetTargetUserIds()
  4. Sends in-app notification via SendBulkNotificationAsync()
  5. Writes audit log entry
→ Returns AnnouncementResponseDTO

Viewing Active Announcements

Any user → GET /api/Announcement/active
→ AnnouncementService.GetActiveAsync(userRole, currentUserId):
  1. Filters: IsPublished=true, EffectiveDate ≤ now, (ExpiryDate ≥ now OR null)
  2. Filters by TargetRoles matches user role
  3. Loads acknowledgments + comments for each announcement
  4. Sets IsAcknowledged flag for current user
→ Returns List<AnnouncementResponseDTO>

Acknowledging

Any user → POST /api/Announcement/{id}/acknowledge
→ AnnouncementService.AcknowledgeAsync():
  1. Checks announcement exists
  2. Checks AnyAsync for duplicate acknowledgment (once-only)
  3. Creates AnnouncementAcknowledgment row
  4. Writes audit log
→ Returns success

9. Notification Behavior

  • When an announcement is published, all targeted users receive an in-app notification via NotificationService.SendBulkNotificationAsync
  • The notification type is NotificationType.TaskAssigned (reused; notification bell shows "New announcement: {title}")
  • Email delivery is handled by the existing NotificationService.SendNotificationAsync which attempts email via MailKit — failure is caught and logged without blocking in-app delivery

10. How to Test

Create an Announcement

  1. Log in as Manager or Coordinator
  2. Go to Announcements sidebar tab
  3. Click "New Announcement"
  4. Fill in title, content, select target audience ("All Users" or a specific role)
  5. Set effective date (and optionally expiry date)
  6. Click "Publish" → announcement appears immediately

View & Acknowledge

  1. Log in as a targeted user (e.g., Dispatcher if you targeted "Dispatcher")
  2. Go to the Announcements tab → the announcement is visible
  3. Click "Acknowledge" → button changes to "Acknowledged", count increments
  4. Try clicking again → it does nothing (once-only enforcement)

Comment

  1. Under any announcement, type a comment in the input field
  2. Press Enter or click the Send button
  3. Comment appears immediately in chronological order with avatar + timestamp

Audience Filtering

  1. Publish an announcement targeting only "Encoder"
  2. Log in as a Dispatcher → announcement is hidden
  3. Log in as an Encoder → announcement is visible

Audit Logs

  1. Go to Activity Logs → filter by module "Announcements"
  2. See entries for: publication, each acknowledgment, each comment
