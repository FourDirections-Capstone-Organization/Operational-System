# Sub-Module 3.1: Task Notifications

## Functional Requirements Covered

| FR ID | Requirement Name | Description | Priority |
|-------|------------------|-------------|----------|
| FR-033 | Basic Notification Alerts | The system shall trigger both in-app and email notifications for task assignments, task updates, and overdue status. | High |
| FR-034 | Configurable Deadline Alerts | Coordinators shall be able to configure the deadline-warning threshold (default: 2 days before due) in hours or days. | High |
| FR-035 | Overdue Escalation | The system shall automatically detect overdue tasks and escalate to the assigned employee, task creator, and Manager. | High |

## 1. High-Level Pseudocode

### What We're Building

We need to create a system where:
1. When a task event happens (assigned, updated, overdue), the system creates an in-app notification AND sends an email
2. Users can see their notifications, mark them as read, and click them to navigate to the related task
3. Coordinators can configure how early deadline warnings should fire (e.g., 2 days before, or 48 hours before)
4. A background job runs every 15 minutes to check for overdue tasks and deadline warnings
5. When a task becomes overdue, it escalates to THREE people: the assigned employee, the task creator (Coordinator), and the Manager

### Step-by-Step Logic

```
STEP 1: Create Enums
├── NotificationType → TaskAssigned, TaskUpdated, TaskOverdue, DeadlineWarning, PushBack, TaskCancelled, TaskResumed, TaskOnHold

├── Message (detailed message)
├── RelatedTaskId (which task this is about - FK to Task, nullable)
├── IsRead (true/false - has the user seen it?)
└── CreatedAt (when it was created)

STEP 3: Create NotificationSettings Model (the configurable deadline threshold)
├── Id (auto-generated GUID)

└── UpdatedAt

STEP 4: Create DTOs
├── NotificationResponseDTO → output for displaying notification data
├── NotificationSettingsDTO → input/output for deadline alert settings

STEP 5: Create NotificationService (the "brain" that handles notifications)
├── CreateNotificationAsync(recipientId, type, title, message, taskId) → create in-app notification

├── GetSettingsAsync() → get current deadline warning settings
```

## 2. High-Level Explanation of Concepts

### Concept 1: In-App Notifications (What it is)

**In-App Notifications** are messages stored in the database that appear inside the application (like a notification bell with a badge showing unread count). They're different from emails because they only exist within the app.

**Why we use it:**
- Immediate visibility - users see notifications when they log in
- Persistent - notifications stay until the user reads/deletes them
- No email dependency - works even if email server is down
- Clickable - users can click to navigate directly to the related task

**How it works:**
```
1. Something happens (e.g., task is assigned to John)
2. System creates a Notification record in the database:
   {
     RecipientId: John's ID,
     Type: TaskAssigned,
     Title: "New Task Assigned",
     Message: "You have been assigned task 'Daily Report Sorting'",
     RelatedTaskId: the task's ID,
     IsRead: false,
     CreatedAt: now
   }
3. When John logs in, the frontend calls GET /api/notifications/unread-count
4. Frontend shows a badge: "3" (3 unread notifications)
5. John clicks the bell icon → frontend calls GET /api/notifications
6. John sees the list of notifications
7. John clicks one → frontend navigates to the task
8. Frontend calls PATCH /api/notifications/{id}/read → marks it as read
```

**Alternatives:**
- **Email only**: No in-app notifications. Users must check email.
- **Push notifications (browser/mobile)**: More intrusive, requires additional setup.
- **SignalR (real-time)**: Push notifications instantly via WebSockets. More complex but more responsive.

**Common Mistakes:**
- Not linking notifications to the related task (users can't navigate to it)
- Not tracking read/unread status
- Creating duplicate notifications for the same event
- Not handling email failures gracefully (in-app should still work)

---

### Concept 2: IHostedService / Background Jobs (What it is)

An **IHostedService** is a background process that runs inside the ASP.NET Core application. It starts when the app starts and runs continuously (or on a timer) without needing user interaction.

**Why we use it:**
- Built into ASP.NET Core (no external packages like Hangfire/Quartz needed)
- Runs automatically - no one needs to trigger it
- Perfect for periodic checks (overdue tasks, deadline warnings)
- Lightweight - doesn't need a separate server or service

**How it works:**
```
1. App starts → OverdueCheckService starts
2. Service runs a loop:
   a. Check all tasks for overdue status
   b. Check all tasks for deadline warnings
   c. Send notifications as needed
   d. Wait 15 minutes
   e. Repeat from step a
3. This runs 24/7 in the background
4. Even if no one is using the app, it still checks

Example timeline:
- 9:00 AM: Check runs. No overdue tasks.
- 9:15 AM: Check runs. Task #123 is overdue! Notify assignee + creator + Manager.
- 9:30 AM: Check runs. Task #456 deadline is in 2 days. Send warning to assignee.
- 9:45 AM: Check runs. No new issues.
```

**Alternatives:**
- **Hangfire**: More features (dashboard, retries, queues) but requires additional packages and database tables.
- **Quartz.NET**: Powerful scheduler but complex configuration.
- **Azure Functions / AWS Lambda**: Cloud-based. Requires cloud infrastructure.
- **Cron jobs (OS-level)**: External to the app. Harder to manage and monitor.

**Common Mistakes:**
- Not handling exceptions (if the check crashes, it stops running)
- Running too frequently (every 10 seconds would hammer the database)
- Not preventing duplicate notifications (checking twice in the same period)
- Not using async/await (blocks the background thread)

### Concept 3: Configurable Deadline Alerts (What it is)

**Configurable Deadline Alerts** means the system has a setting that controls WHEN deadline warning notifications are sent. By default, warnings go out 2 days before the deadline, but Coordinators can change this to any value (e.g., 48 hours, 1 day, 3 days).

**Why we use it:**
- Flexibility - different teams may need different warning times
- Adaptability - as workflows change, the threshold can be adjusted
- No code changes needed - Coordinators can change it through the UI

**How it works:**
```
SETTINGS TABLE (only one row):
{
  DeadlineWarningValue: 2,
  DeadlineWarningUnit: Days
}

MEANING: "Send a warning 2 Days before the deadline"

BACKGROUND CHECK LOGIC:
1. Get the settings: Value = 2, Unit = Days
2. Calculate the threshold time: 2 days = 48 hours
3. For each active task:
   a. Calculate remaining time: task.Deadline - Now
   b. If remaining time <= 48 hours AND remaining time > 0:
      → Send deadline warning notification to assignee
   c. If remaining time <= 0 (past deadline):
      → Task is overdue → escalate

CHANGING THE SETTING:
1. Coordinator goes to Notification Settings
2. Changes threshold to: Value = 24, Unit = Hours
3. System saves: { Value: 24, Unit: Hours }
4. From now on, warnings go out 24 hours before deadline (not 48)
```

**Alternatives:**
- **Hardcoded value**: Always 2 days. Simple but inflexible.
- **Per-task threshold**: Each task has its own warning time. More complex.
- **Per-user threshold**: Each user gets warnings at their preferred time. Too complex.

**Common Mistakes:**
- Not seeding default settings (app crashes on first run)
- Not validating the threshold value (negative numbers, zero)
- Sending duplicate warnings (checking too frequently without deduplication)
- Not handling the unit conversion correctly (Hours vs Days)

### Concept 4: Overdue Escalation (What it is)

**Overdue Escalation** is when a task's deadline passes without the task being completed. The system automatically notifies THREE people: the assigned employee, the task creator (Coordinator), and the Manager.

**Why we use it:**
- Accountability - everyone involved knows the task is late
- Urgency - multiple notifications create pressure to resolve
- Visibility - Manager can see and intervene if needed

**How it works:**
```
BACKGROUND CHECK (runs every 15 minutes):

1. Find all tasks where:
   - Status is NOT Completed
   - Status is NOT Cancelled
   - Deadline < Now (past the deadline)

2. For each overdue task:
   a. Check if we already sent an escalation for this task
      (to avoid notifying 4 times a day for the same task)
   b. If NOT already escalated:
      - Create notification for assigned employee:
        "Your task 'Daily Report' is overdue. Deadline was Jan 15, 2024."
      - Create notification for task creator:
        "Task 'Daily Report' created by you is now overdue."
      - Create notification for Manager:
        "Task 'Daily Report' is overdue. Assigned to John Doe."
      - Send email to all three
      - Mark task as escalated (so we don't notify again)

3. The task is visually flagged as "Overdue" in Task Management views
```

**Key Rules:**
- Only notifies once per overdue task (not every 15 minutes)
- Sends to THREE people: assignee, creator, Manager
- Sends both in-app AND email notifications
- Email failure doesn't prevent in-app notification

**Alternatives:**
- **Notify only assignee**: Not enough visibility for Manager.
- **Notify entire department**: Too many people, creates noise.
- **Progressive escalation**: First notify assignee, then after 1 day notify Manager. More nuanced but more complex.

**Common Mistakes:**
- Not preventing duplicate escalations (spamming notifications)
- Not including all three recipients
- Not checking if the task is already Completed/Cancelled
- Not flagging the task as overdue in the UI

```csharp
using Microsoft.EntityFrameworkCore;
using Backend.Data;
using Backend.Models;
using Backend.Models.DTOs;
using Backend.Models.Enums;
using Backend.Modules.Email;

namespace Backend.Modules.Notifications;

public class NotificationService : INotificationService
{
    private readonly AppDbContext _db;
    private readonly IEmailService _emailService;
    private readonly ILogger<NotificationService> _logger;

    public NotificationService(AppDbContext db, IEmailService emailService, ILogger<NotificationService> logger)
    {
        _db = db;
        _emailService = emailService;
        _logger = logger;
    }

    public async Task<Notification> CreateNotificationAsync(
        Guid recipientId, NotificationType type, string title, string message, Guid? taskId = null)
    {
        var notification = new Notification
        {
            RecipientId = recipientId,
            Type = type,
            Title = title,
            Message = message,
            RelatedTaskId = taskId,
            IsRead = false,
            CreatedAt = DateTime.UtcNow
        };

        _db.Notifications.Add(notification);
        await _db.SaveChangesAsync();

        return notification;
    }

    public async Task SendNotificationAsync(
        Guid recipientId, NotificationType type, string title, string message, Guid? taskId = null)
    {
        await CreateNotificationAsync(recipientId, type, title, message, taskId);

        var recipient = await _db.Users.FindAsync(recipientId);
        if (recipient is not null)
        {
            var fullName = $"{recipient.FirstName} {recipient.LastName}".Trim();
            try
            {
                await _emailService.SendTaskNotificationEmailAsync(
                    recipient.Email, fullName, title, message);
            }
            catch (Exception ex)
            {
                _logger.LogWarning(ex, "Failed to send email notification to {Email}", recipient.Email);
            }
        }
    }

    public async Task SendBulkNotificationAsync(
        List<Guid> recipientIds, NotificationType type, string title, string message, Guid? taskId = null)
    {
        foreach (var recipientId in recipientIds)
        {
            await SendNotificationAsync(recipientId, type, title, message, taskId);
        }
    }

    public async Task<ApiResponseDTO<List<NotificationResponseDTO>>> GetByRecipientAsync(Guid recipientId)
    {
        var notifications = await _db.Notifications
            .Where(n => n.RecipientId == recipientId)
            .OrderByDescending(n => n.CreatedAt)
            .Select(n => new NotificationResponseDTO
            {
                Id = n.Id,
                Type = n.Type,
                Title = n.Title,
                Message = n.Message,
                RelatedTaskId = n.RelatedTaskId,
                IsRead = n.IsRead,
                CreatedAt = n.CreatedAt
            })
            .ToListAsync();

        return ApiResponseDTO<List<NotificationResponseDTO>>.Success(notifications);
    }

    public async Task<ApiResponseDTO<int>> GetUnreadCountAsync(Guid recipientId)
    {
        var count = await _db.Notifications
            .CountAsync(n => n.RecipientId == recipientId && !n.IsRead);

        return ApiResponseDTO<int>.Success(count);
    }

    public async Task<ApiResponseDTO<bool>> MarkAsReadAsync(Guid notificationId, Guid recipientId)
    {
        var notification = await _db.Notifications
            .FirstOrDefaultAsync(n => n.Id == notificationId && n.RecipientId == recipientId);

        if (notification is null)
            return ApiResponseDTO<bool>.Failure("Notification not found");

        notification.IsRead = true;
        await _db.SaveChangesAsync();

        return ApiResponseDTO<bool>.Success(true);
    }

    public async Task<ApiResponseDTO<bool>> MarkAllAsReadAsync(Guid recipientId)
    {
        var unreadNotifications = await _db.Notifications
            .Where(n => n.RecipientId == recipientId && !n.IsRead)
            .ToListAsync();

        foreach (var notification in unreadNotifications)
        {
            notification.IsRead = true;
        }

        await _db.SaveChangesAsync();

        return ApiResponseDTO<bool>.Success(true, "All notifications marked as read");
    }
}
```

```csharp
using Backend.Models;

{
```

```csharp
    }

    public async Task<ApiResponseDTO<NotificationSettingsDTO>> GetSettingsAsync()
    {
        var settings = await _db.NotificationSettings.FirstOrDefaultAsync();

        if (settings is null)
        {
            settings = new NotificationSettings
            {
                DeadlineWarningValue = 2,

            DeadlineWarningValue = settings.DeadlineWarningValue,
            DeadlineWarningUnit = settings.DeadlineWarningUnit
        };

        return ApiResponseDTO<NotificationSettingsDTO>.Success(response);
    }

    public async Task<ApiResponseDTO<NotificationSettingsDTO>> UpdateSettingsAsync(NotificationSettingsDTO dto)
    {
        if (dto.DeadlineWarningValue <= 0)
            return ApiResponseDTO<NotificationSettingsDTO>.Failure("Threshold value must be a positive number");

        var settings = await _db.NotificationSettings.FirstOrDefaultAsync();

        if (settings is null)
        {
            settings = new NotificationSettings();
            _db.NotificationSettings.Add(settings);
        }

        settings.DeadlineWarningValue = dto.DeadlineWarningValue;
        settings.DeadlineWarningUnit = dto.DeadlineWarningUnit;
        settings.UpdatedAt = DateTime.UtcNow;

        await _db.SaveChangesAsync();

        var response = new NotificationSettingsDTO
        {
            DeadlineWarningValue = settings.DeadlineWarningValue,
            DeadlineWarningUnit = settings.DeadlineWarningUnit
        };

        return ApiResponseDTO<NotificationSettingsDTO>.Success(response, "Deadline warning threshold updated successfully");
    }

    public async Task<NotificationSettings> GetSettingsEntityAsync()
    {
        var settings = await _db.NotificationSettings.FirstOrDefaultAsync();

        if (settings is null)
        {
            settings = new NotificationSettings
            {
                DeadlineWarningValue = 2,
                DeadlineWarningUnit = Models.Enums.DeadlineWarningUnit.Days,
                UpdatedAt = DateTime.UtcNow

                DeadlineWarningValue = 2,
                DeadlineWarningUnit = Models.Enums.DeadlineWarningUnit.Days,
                UpdatedAt = DateTime.UtcNow
            });

            await _db.SaveChangesAsync();
        }
    }
```

### Step 7: Create OverdueCheckService (Background Job)

**File: `backend/Modules/Notifications/OverdueCheckService.cs`**

```csharp
using Microsoft.EntityFrameworkCore;
using Backend.Data;
using Backend.Models;
using Backend.Models.Enums;

namespace Backend.Modules.Notifications;

public class OverdueCheckService : BackgroundService
{
    private readonly IServiceProvider _serviceProvider;
    private readonly ILogger<OverdueCheckService> _logger;
    private readonly TimeSpan _checkInterval = TimeSpan.FromMinutes(15);

    public OverdueCheckService(IServiceProvider serviceProvider, ILogger<OverdueCheckService> logger)
    {
        _serviceProvider = serviceProvider;
        _logger = logger;
    }

    protected override async Task ExecuteAsync(CancellationToken stoppingToken)
    {
        _logger.LogInformation("Overdue Check Service started. Checking every {Interval} minutes",
            _checkInterval.TotalMinutes);

        while (!stoppingToken.IsCancellationRequested)
        {
            try
            {
                await CheckOverdueTasksAsync(stoppingToken);
                await CheckDeadlineWarningsAsync(stoppingToken);
            }
            catch (Exception ex)
            {
                _logger.LogError(ex, "Error during overdue/deadline check");
            }

            await Task.Delay(_checkInterval, stoppingToken);
        }
    }

    private async Task CheckOverdueTasksAsync(CancellationToken stoppingToken)
    {
        using var scope = _serviceProvider.CreateScope();
        var db = scope.ServiceProvider.GetRequiredService<AppDbContext>();
        var notificationService = scope.ServiceProvider.GetRequiredService<INotificationService>();

        var now = DateTime.UtcNow;

        var overdueTasks = await db.Tasks
            .Include(t => t.Assignments)
            .Include(t => t.CreatedBy)
            .Where(t => t.Deadline < now
                && t.Status != TaskStatus.Completed
                && t.Status != TaskStatus.Cancelled)
            .ToListAsync(stoppingToken);

        foreach (var task in overdueTasks)
        {
            var alreadyNotified = await db.Notifications
                .AnyAsync(n => n.RelatedTaskId == task.Id
                    && n.Type == NotificationType.TaskOverdue, stoppingToken);

            if (alreadyNotified)
                continue;

            var recipientIds = new List<Guid>();

            foreach (var assignment in task.Assignments)
            {
                recipientIds.Add(assignment.AssignedUserId);
            }

            if (task.CreatedById != Guid.Empty)
                recipientIds.Add(task.CreatedById);

            var managers = await db.Users
                .Where(u => u.Role == UserRole.Manager && u.IsActive && !u.IsDeactivated)
                .Select(u => u.Id)
                .ToListAsync(stoppingToken);

            recipientIds.AddRange(managers);

            recipientIds = recipientIds.Distinct().ToList();

            var taskTitle = task.Title.Length > 50 ? task.Title[..50] + "..." : task.Title;

            await notificationService.SendBulkNotificationAsync(
                recipientIds,
                NotificationType.TaskOverdue,
                "Task Overdue",
                $"Task '{taskTitle}' is overdue. Deadline was {task.Deadline:MMM dd, yyyy h:mm tt}.",
                task.Id);

            _logger.LogInformation("Overdue escalation sent for task {TaskId}: {TaskTitle}",
                task.Id, task.Title);
        }
    }

    private async Task CheckDeadlineWarningsAsync(CancellationToken stoppingToken)
    {
        using var scope = _serviceProvider.CreateScope();
        var db = scope.ServiceProvider.GetRequiredService<AppDbContext>();
        var notificationService = scope.ServiceProvider.GetRequiredService<INotificationService>();
        var settingsService = scope.ServiceProvider.GetRequiredService<INotificationSettingsService>();

        var settings = await settingsService.GetSettingsEntityAsync();
        var now = DateTime.UtcNow;

        var warningThreshold = settings.DeadlineWarningUnit == DeadlineWarningUnit.Days
            ? TimeSpan.FromDays(settings.DeadlineWarningValue)
            : TimeSpan.FromHours(settings.DeadlineWarningValue);

        var activeTasks = await db.Tasks
            .Include(t => t.Assignments)
            .Where(t => t.Status != TaskStatus.Completed
                && t.Status != TaskStatus.Cancelled
                && t.Deadline > now)
            .ToListAsync(stoppingToken);

        foreach (var task in activeTasks)
        {
            var remainingTime = task.Deadline - now;

            if (remainingTime > warningThreshold)
                continue;

            var alreadyWarned = await db.Notifications
                .AnyAsync(n => n.RelatedTaskId == task.Id
                    && n.Type == NotificationType.DeadlineWarning, stoppingToken);

            if (alreadyWarned)
                continue;

            var assigneeIds = task.Assignments.Select(a => a.AssignedUserId).ToList();

            if (assigneeIds.Count == 0)
                continue;

            var taskTitle = task.Title.Length > 50 ? task.Title[..50] + "..." : task.Title;
            var remainingFormatted = remainingTime.TotalDays >= 1
                ? $"{remainingTime.TotalDays:F1} days"
                : $"{remainingTime.TotalHours:F1} hours";

            await notificationService.SendBulkNotificationAsync(
                assigneeIds,
                NotificationType.DeadlineWarning,
                "Deadline Approaching",
                $"Task '{taskTitle}' is due in {remainingFormatted} ({task.Deadline:MMM dd, yyyy h:mm tt}).",
                task.Id);

            _logger.LogInformation("Deadline warning sent for task {TaskId}: due in {Remaining}",
                task.Id, remainingFormatted);
        }
    }
}
```
