# Sub-Module 2.2: Task Workflow (Finite State Machine)

## Functional Requirements Covered

| FR ID | Requirement Name | Description | Priority |
|-------|------------------|-------------|----------|
| FR-022 | FSM Progression Enforcement | Tasks must progress in exact order: Not Started → In Progress → Done/Pending Review → Completed. No skipping states. | High |
| FR-023 | Workflow Reversal (Push Back) | Coordinators can push back a task from Done/Pending Review to In Progress with a mandatory comment. | High |
| FR-024 | Task Completion Restriction | Only Coordinators/Managers can approve tasks to Completed. Employees can only advance to Done/Pending Review. | High |
| FR-025 | On-Hold Pause Mechanism | Coordinators can place tasks On Hold (pausing SLA) and resume with a revised deadline. | High |
| FR-026 | Task Cancellation | Coordinators can cancel active tasks (Not Started, In Progress, On Hold) with a mandatory reason. | High |

---

## 1. High-Level Pseudocode

### What We're Building

We need to create a system where:
1. Tasks follow a strict workflow: Not Started → In Progress → Done/Pending Review → Completed
2. Only the assigned employee can move a task forward (Not Started → In Progress → Done)
3. Only Coordinators/Managers can approve a task to Completed
4. Coordinators can push back a Done task to In Progress (with mandatory comment)
5. Coordinators can pause a task (On Hold) and resume it with a new deadline
6. Coordinators can cancel active tasks with a mandatory reason

### Step-by-Step Logic

```
STEP 1: Understand the State Machine (the "rules" for status changes)
├── A state machine is like a board game - you can only move to certain spaces from where you are
├── Define which transitions are ALLOWED:
│   ├── NotStarted → InProgress (only assigned employee)
│   ├── InProgress → DonePendingReview (only assigned employee)
│   ├── DonePendingReview → Completed (only Coordinator/Manager)
│   ├── DonePendingReview → InProgress (Push Back - only Coordinator)
│   ├── NotStarted → OnHold (only Coordinator)
│   ├── InProgress → OnHold (only Coordinator)
│   ├── OnHold → NotStarted or InProgress (Resume - only Coordinator)
│   ├── NotStarted → Cancelled (only Coordinator)
│   ├── InProgress → Cancelled (only Coordinator)
│   └── OnHold → Cancelled (only Coordinator)
└── Any other transition is REJECTED

STEP 2: Create TaskWorkflowService (the "brain" that enforces the rules)
├── UpdateStatusAsync(taskId, newStatus, userId) → check if transition is allowed, apply it
├── PushBackAsync(taskId, comment, coordinatorId) → revert from Done to In Progress
├── ReviewTaskAsync(taskId, decision, remarks, reviewerId) → approve or return for rework
├── PlaceOnHoldAsync(taskId, reason, coordinatorId) → pause task and SLA
├── ResumeTaskAsync(taskId, revisedDeadline, coordinatorId) → resume with new deadline
└── CancelTaskAsync(taskId, reason, coordinatorId) → cancel active task

STEP 3: Create DTOs (the "forms" for workflow actions)
├── TaskStatusUpdateDTO → input for status change (new status + progress notes)
├── PushBackDTO → input for push back (mandatory comment)
├── ReviewTaskDTO → input for review (approve/reject + remarks)
├── PlaceOnHoldDTO → input for hold (mandatory reason)
├── ResumeTaskDTO → input for resume (mandatory revised deadline)
└── CancelTaskDTO → input for cancel (mandatory reason + confirmation)

STEP 4: Create TaskWorkflowController endpoints
├── PATCH /api/tasks/{id}/status → update status (FSM enforced)
├── PATCH /api/tasks/{id}/push-back → push back to In Progress
├── PATCH /api/tasks/{id}/review → approve or return for rework
├── PATCH /api/tasks/{id}/hold → place on hold
├── PATCH /api/tasks/{id}/resume → resume from hold
└── PATCH /api/tasks/{id}/cancel → cancel task

STEP 5: Add role-based checks
├── Assigned employee check → only they can advance NotStarted → InProgress → Done
├── Coordinator/Manager check → only they can approve to Completed
├── Coordinator check → only they can push back, hold, resume, cancel
└── Completed tasks → locked from all modifications

STEP 6: Handle SLA pause/resume
├── On Hold → save current status as PreviousStatus, record HeldAt timestamp
├── Resume → restore PreviousStatus, set new RevisedDeadline
└── SLA countdown → calculated from RevisedDeadline (not original deadline)
```

## 2. High-Level Explanation of Concepts

### Concept 1: Finite State Machine / FSM (What it is)

A **Finite State Machine (FSM)** is a system that manages transitions between a fixed set of states. Think of it like a vending machine:
- State 1: Waiting for money
- State 2: Money inserted, waiting for selection
- State 3: Dispensing product
- You can't go from "Waiting for money" directly to "Dispensing product" - you must go through the steps in order.

**Why we use it:**
- Enforces business rules (tasks MUST follow the proper workflow)
- Prevents invalid actions (can't skip from Not Started to Completed)
- Makes the system predictable (everyone knows the exact flow)
- Easy to audit (every transition is tracked)

**How it works:**
```
ALLOWED TRANSITIONS (the "rules"):

NotStarted ──→ InProgress ──→ DonePendingReview ──→ Completed
    │               ↑                  │
    │               │                  │ (Push Back)
    │               └──────────────────┘
    │
    ├──→ OnHold ──→ (Resume) ──→ NotStarted or InProgress
    │
    └──→ Cancelled

InProgress ──→ OnHold ──→ (Resume) ──→ InProgress
InProgress ──→ Cancelled

DonePendingReview ──→ InProgress (Push Back by Coordinator)

RULES:
- Only assigned employee: NotStarted → InProgress → DonePendingReview
- Only Coordinator/Manager: DonePendingReview → Completed
- Only Coordinator: Push Back, On Hold, Resume, Cancel
- Completed tasks: LOCKED (no changes allowed)
```

**Alternatives:**
- **No workflow enforcement**: Anyone can set any status. Chaos - no accountability.
- **Custom workflow engine (like Windows Workflow Foundation)**: Overkill for our needs.
- **Database-driven workflow**: Store transitions in a config table. More flexible but more complex.

**Common Mistakes:**
- Not checking the current status before allowing a transition
- Forgetting to check WHO is making the transition (role-based access)
- Allowing transitions on Completed/Cancelled tasks
- Not recording rejected transition attempts in the audit log

---

### Concept 2: Push Back / Workflow Reversal (What it is)

**Push Back** is when a Coordinator reviews a submitted task and says "This isn't done correctly, go back and fix it." The task moves from Done/Pending Review back to In Progress.

**Why we use it:**
- Quality control - ensures work meets standards before final approval
- Accountability - the employee must fix issues, not just submit and forget
- Communication - the mandatory comment explains what needs to be fixed

**How it works:**
```
1. Employee submits task → Status becomes "Done/Pending Review"
2. Coordinator reviews the work
3. Coordinator finds issues → clicks "Push Back"
4. System requires: "Why are you pushing this back?" (mandatory comment)
5. Coordinator enters comment → submits
6. System changes status: Done/Pending Review → In Progress
7. System saves the comment (linked to the task)
8. System notifies the employee: "Your task was pushed back. Reason: [comment]"
9. Employee fixes the issues → submits again → back to Done/Pending Review
```

**Key Rules:**
- Only Coordinators can push back (not Managers, not employees)
- Only tasks in "Done/Pending Review" can be pushed back
- A comment is MANDATORY (can't push back without explaining why)
- The task goes back to "In Progress" (not "Not Started")

**Common Mistakes:**
- Allowing push back without a comment (defeats the purpose)
- Pushing back to "Not Started" instead of "In Progress" (loses progress)
- Allowing employees to push back their own tasks
- Not notifying the employee of the push back

---

### Concept 3: Task Completion Restriction (What it is)

**Task Completion Restriction** means that regular employees (Dispatcher, Encoder, Courier) CANNOT mark a task as "Completed." They can only mark it as "Done/Pending Review." A Coordinator or Manager must review and approve it.

**Why we use it:**
- Quality assurance - a second pair of eyes reviews the work
- Accountability - Coordinators are responsible for final approval
- Compliance - creates an audit trail of who did the work and who approved it

**How it works:**
```
Employee workflow:
1. Employee works on task
2. Employee clicks "Mark as Done"
3. System checks: "Is this user a Dispatcher/Encoder/Courier?"
4. If yes → Status becomes "Done/Pending Review" (NOT "Completed")
5. System notifies Coordinator: "Task XYZ is awaiting your review"

Coordinator/Manager workflow:
1. Coordinator sees task in "Done/Pending Review" status
2. Coordinator reviews the work
3. Coordinator clicks "Approve & Close" OR "Return for Rework"
4. If Approve → Status becomes "Completed" (task is locked)
5. If Return for Rework → Status becomes "In Progress" (push back)
```

**Key Rules:**
- Employees can only advance to "Done/Pending Review"
- Only Coordinators/Managers can approve to "Completed"
- Completed tasks are LOCKED (no standard modifications)
- The only way to reverse a Completed task is through Push Back (FR-023)

**Common Mistakes:**
- Allowing employees to set status to "Completed" directly
- Not locking Completed tasks (someone could change the data)
- Not checking the user's role before allowing approval
- Forgetting that Completed tasks should be read-only

---

### Concept 4: On-Hold Pause Mechanism (What it is)

**On-Hold** is when a Coordinator pauses a task because something is blocking progress (e.g., waiting for client information, missing resources). The SLA countdown is PAUSED during this time.

**Why we use it:**
- Fairness - employees shouldn't be penalized for delays outside their control
- Accuracy - SLA timers should only count actual work time
- Transparency - the hold reason explains why the task is paused

**How it works:**
```
PLACING ON HOLD:
1. Coordinator opens an active task (Not Started or In Progress)
2. Coordinator clicks "Place On Hold"
3. System requires: "Why are you placing this on hold?" (mandatory reason)
4. Coordinator enters reason → submits
5. System saves current status as PreviousStatus (e.g., "InProgress")
6. System changes status to "OnHold"
7. System records HeldAt timestamp (when the hold started)
8. SLA countdown is PAUSED
9. System notifies assigned employee: "Your task is on hold. Reason: [reason]"

RESUMING:
1. Coordinator resolves the blocking issue
2. Coordinator clicks "Resume Task"
3. System requires: "What's the new deadline?" (mandatory revised deadline)
4. Coordinator enters new deadline → submits
5. System validates: new deadline must be in the future
6. System restores PreviousStatus (e.g., back to "InProgress")
7. System sets RevisedDeadline to the new deadline
8. SLA countdown RESTARTS from the revised deadline
9. System notifies employee: "Your task has been resumed. New deadline: [date]"
```

**Key Rules:**
- Only Coordinators can place on hold or resume
- Hold reason is MANDATORY
- Revised deadline is MANDATORY and must be in the future
- SLA countdown restarts from the revised deadline (not the original)
- PreviousStatus is saved so we know what to restore

**Common Mistakes:**
- Not saving PreviousStatus (won't know what to restore)
- Not pausing the SLA countdown (employee gets penalized unfairly)
- Allowing resume without a revised deadline
- Using the original deadline instead of the revised one for SLA calculations

---

### Concept 5: Task Cancellation (What it is)

**Task Cancellation** is when a Coordinator decides a task is no longer needed and cancels it. Only active tasks (Not Started, In Progress, On Hold) can be cancelled. Completed tasks cannot be cancelled.

**Why we use it:**
- Flexibility - business needs change, sometimes tasks are no longer relevant
- Cleanliness - removes clutter from active task lists
- Audit trail - the cancellation reason explains why it was cancelled

**How it works:**
```
1. Coordinator opens an active task (Not Started, In Progress, or On Hold)
2. Coordinator clicks "Cancel Task"
3. System shows confirmation dialog: "Are you sure? This cannot be undone."
4. System requires: "Why are you cancelling this task?" (mandatory reason)
5. System requires: Confirmation checkbox (extra safety)
6. Coordinator enters reason + checks box → confirms
7. System checks: "Is this task already Completed?" → If yes, REJECT
8. System changes status to "Cancelled"
9. System saves CancellationReason
10. System notifies assigned employee(s): "Your task has been cancelled. Reason: [reason]"
```

**Key Rules:**
- Only Coordinators can cancel tasks
- Only active tasks can be cancelled (Not Started, In Progress, On Hold)
- Completed tasks CANNOT be cancelled
- Cancellation reason is MANDATORY
- Confirmation is required (prevents accidental cancellation)

**Common Mistakes:**
- Allowing cancellation of Completed tasks
- Not requiring a reason (no audit trail)
- Not notifying assigned employees
- Not checking if the task is already Cancelled

**File: `backend/Modules/TaskManagement/TaskWorkflowService.cs`**

```csharp
using Microsoft.EntityFrameworkCore;
using Backend.Data;
using Backend.Models;
using Backend.Models.DTOs;
using Backend.Models.Enums;

namespace Backend.Modules.TaskManagement;

public class TaskWorkflowService : ITaskWorkflowService
{
    private readonly AppDbContext _db;

    public TaskWorkflowService(AppDbContext db)
    {
        _db = db;
    }

    public async Task<ApiResponseDTO<TaskResponseDTO>> UpdateStatusAsync(
        Guid taskId, TaskStatusUpdateDTO dto, Guid userId)
    {
        var task = await _db.Tasks
            .Include(t => t.Assignments)
            .Include(t => t.CreatedBy)
            .Include(t => t.AssignedDepartment)
            .FirstOrDefaultAsync(t => t.Id == taskId);

        if (task is null)
            return ApiResponseDTO<TaskResponseDTO>.Failure("Task not found");

        var user = await _db.Users.FindAsync(userId);
        if (user is null)
            return ApiResponseDTO<TaskResponseDTO>.Failure("User not found");

        var currentStatus = task.Status;
        var newStatus = dto.NewStatus;

        var transitionCheck = ValidateTransition(currentStatus, newStatus, user, task, userId);
        if (!transitionCheck.IsValid)
            return ApiResponseDTO<TaskResponseDTO>.Failure(transitionCheck.ErrorMessage!);

        task.Status = newStatus;
        task.UpdatedAt = DateTime.UtcNow;

        await _db.SaveChangesAsync();

        return ApiResponseDTO<TaskResponseDTO>.Success(
            await MapToResponseDTOAsync(task),
            "Task status updated successfully");
    }

    public async Task<ApiResponseDTO<TaskResponseDTO>> PushBackAsync(
        Guid taskId, PushBackDTO dto, Guid coordinatorId)
    {
        var task = await _db.Tasks
            .Include(t => t.Assignments)
            .Include(t => t.CreatedBy)
            .Include(t => t.AssignedDepartment)
            .FirstOrDefaultAsync(t => t.Id == taskId);

        if (task is null)
            return ApiResponseDTO<TaskResponseDTO>.Failure("Task not found");

        var coordinator = await _db.Users.FindAsync(coordinatorId);
        if (coordinator is null)
            return ApiResponseDTO<TaskResponseDTO>.Failure("User not found");

        if (coordinator.Role != UserRole.Coordinator)
            return ApiResponseDTO<TaskResponseDTO>.Failure("Only Coordinators can push back tasks");

        if (task.Status != TaskStatus.DonePendingReview)
            return ApiResponseDTO<TaskResponseDTO>.Failure(
                "Only tasks in Done/Pending Review status may be pushed back");

        if (string.IsNullOrWhiteSpace(dto.Comment))
            return ApiResponseDTO<TaskResponseDTO>.Failure(
                "A comment is required to push back a task");

        task.Status = TaskStatus.InProgress;
        task.UpdatedAt = DateTime.UtcNow;

        await _db.SaveChangesAsync();

        return ApiResponseDTO<TaskResponseDTO>.Success(
            await MapToResponseDTOAsync(task),
            "Task pushed back to In Progress successfully");
    }

    public async Task<ApiResponseDTO<TaskResponseDTO>> ReviewTaskAsync(
        Guid taskId, ReviewTaskDTO dto, Guid reviewerId)
    {
        var task = await _db.Tasks
            .Include(t => t.Assignments)
            .Include(t => t.CreatedBy)
            .Include(t => t.AssignedDepartment)
            .FirstOrDefaultAsync(t => t.Id == taskId);

        if (task is null)
            return ApiResponseDTO<TaskResponseDTO>.Failure("Task not found");

        var reviewer = await _db.Users.FindAsync(reviewerId);
        if (reviewer is null)
            return ApiResponseDTO<TaskResponseDTO>.Failure("User not found");

        if (reviewer.Role != UserRole.Coordinator && reviewer.Role != UserRole.Manager)
            return ApiResponseDTO<TaskResponseDTO>.Failure(
                "Only Coordinators and Managers can review tasks");

        if (task.Status != TaskStatus.DonePendingReview)
            return ApiResponseDTO<TaskResponseDTO>.Failure(
                "Only tasks in Done/Pending Review status can be reviewed");

        if (dto.IsApproved)
        {
            task.Status = TaskStatus.Completed;
            task.UpdatedAt = DateTime.UtcNow;

            await _db.SaveChangesAsync();

            return ApiResponseDTO<TaskResponseDTO>.Success(
                await MapToResponseDTOAsync(task),
                "Task approved and officially closed");
        }
        else
        {
            if (string.IsNullOrWhiteSpace(dto.Remarks))
                return ApiResponseDTO<TaskResponseDTO>.Failure(
                    "Remarks are required when returning a task for rework");

            task.Status = TaskStatus.InProgress;
            task.UpdatedAt = DateTime.UtcNow;

            await _db.SaveChangesAsync();

            return ApiResponseDTO<TaskResponseDTO>.Success(
                await MapToResponseDTOAsync(task),
                "Task returned for rework");
        }
    }

    public async Task<ApiResponseDTO<TaskResponseDTO>> PlaceOnHoldAsync(
        Guid taskId, PlaceOnHoldDTO dto, Guid coordinatorId)
    {
        var task = await _db.Tasks
            .Include(t => t.Assignments)
            .Include(t => t.CreatedBy)
            .Include(t => t.AssignedDepartment)
            .FirstOrDefaultAsync(t => t.Id == taskId);

        if (task is null)
            return ApiResponseDTO<TaskResponseDTO>.Failure("Task not found");

        var coordinator = await _db.Users.FindAsync(coordinatorId);
        if (coordinator is null)
            return ApiResponseDTO<TaskResponseDTO>.Failure("User not found");

        if (coordinator.Role != UserRole.Coordinator)
            return ApiResponseDTO<TaskResponseDTO>.Failure("Only Coordinators can place tasks on hold");

        if (task.Status != TaskStatus.NotStarted && task.Status != TaskStatus.InProgress)
            return ApiResponseDTO<TaskResponseDTO>.Failure(
                "Only tasks in Not Started or In Progress status can be placed on hold");

        if (string.IsNullOrWhiteSpace(dto.HoldReason))
            return ApiResponseDTO<TaskResponseDTO>.Failure("Hold reason is required");

        task.PreviousStatus = task.Status;
        task.Status = TaskStatus.OnHold;
        task.HoldReason = dto.HoldReason.Trim();
        task.HeldAt = DateTime.UtcNow;
        task.UpdatedAt = DateTime.UtcNow;

        await _db.SaveChangesAsync();

        return ApiResponseDTO<TaskResponseDTO>.Success(
            await MapToResponseDTOAsync(task),
            "Task placed on hold successfully");
    }

    public async Task<ApiResponseDTO<TaskResponseDTO>> ResumeTaskAsync(
        Guid taskId, ResumeTaskDTO dto, Guid coordinatorId)
    {
        var task = await _db.Tasks
            .Include(t => t.Assignments)
            .Include(t => t.CreatedBy)
            .Include(t => t.AssignedDepartment)
            .FirstOrDefaultAsync(t => t.Id == taskId);

        if (task is null)
            return ApiResponseDTO<TaskResponseDTO>.Failure("Task not found");

        var coordinator = await _db.Users.FindAsync(coordinatorId);
        if (coordinator is null)
            return ApiResponseDTO<TaskResponseDTO>.Failure("User not found");

        if (coordinator.Role != UserRole.Coordinator)
            return ApiResponseDTO<TaskResponseDTO>.Failure("Only Coordinators can resume tasks");

        if (task.Status != TaskStatus.OnHold)
            return ApiResponseDTO<TaskResponseDTO>.Failure(
                "Only tasks in On Hold status can be resumed");

        if (dto.RevisedDeadline <= DateTime.UtcNow)
            return ApiResponseDTO<TaskResponseDTO>.Failure(
                "Revised deadline is required and must be a future date/time");

        if (!task.PreviousStatus.HasValue)
            return ApiResponseDTO<TaskResponseDTO>.Failure(
                "Cannot resume task: previous status not recorded");

        task.Status = task.PreviousStatus.Value;
        task.RevisedDeadline = dto.RevisedDeadline;
        task.Deadline = dto.RevisedDeadline;
        task.PreviousStatus = null;
        task.HoldReason = null;
        task.HeldAt = null;
        task.UpdatedAt = DateTime.UtcNow;

        await _db.SaveChangesAsync();

        return ApiResponseDTO<TaskResponseDTO>.Success(
            await MapToResponseDTOAsync(task),
            "Task resumed successfully");
    }

    public async Task<ApiResponseDTO<TaskResponseDTO>> CancelTaskAsync(
        Guid taskId, CancelTaskDTO dto, Guid coordinatorId)
    {
        var task = await _db.Tasks
            .Include(t => t.Assignments)
            .Include(t => t.CreatedBy)
            .Include(t => t.AssignedDepartment)
            .FirstOrDefaultAsync(t => t.Id == taskId);

        if (task is null)
            return ApiResponseDTO<TaskResponseDTO>.Failure("Task not found");

        var coordinator = await _db.Users.FindAsync(coordinatorId);
        if (coordinator is null)
            return ApiResponseDTO<TaskResponseDTO>.Failure("User not found");

        if (coordinator.Role != UserRole.Coordinator)
            return ApiResponseDTO<TaskResponseDTO>.Failure("Only Coordinators can cancel tasks");

        if (task.Status == TaskStatus.Completed)
            return ApiResponseDTO<TaskResponseDTO>.Failure("Completed tasks cannot be cancelled");

        if (task.Status == TaskStatus.Cancelled)
            return ApiResponseDTO<TaskResponseDTO>.Failure("Task is already cancelled");

        var activeStatuses = new[] { TaskStatus.NotStarted, TaskStatus.InProgress, TaskStatus.OnHold };
        if (!activeStatuses.Contains(task.Status))
            return ApiResponseDTO<TaskResponseDTO>.Failure(
                "Only active tasks (Not Started, In Progress, or On Hold) can be cancelled");

        if (string.IsNullOrWhiteSpace(dto.CancellationReason))
            return ApiResponseDTO<TaskResponseDTO>.Failure("Cancellation reason is required");

        if (!dto.IsConfirmed)
            return ApiResponseDTO<TaskResponseDTO>.Failure("Cancellation must be confirmed");

        task.Status = TaskStatus.Cancelled;
        task.CancellationReason = dto.CancellationReason.Trim();
        task.UpdatedAt = DateTime.UtcNow;

        await _db.SaveChangesAsync();

        return ApiResponseDTO<TaskResponseDTO>.Success(
            await MapToResponseDTOAsync(task),
            "Task cancelled successfully");
    }

    private (bool IsValid, string? ErrorMessage) ValidateTransition(
        TaskStatus currentStatus, TaskStatus newStatus, User user, Models.Task task, Guid userId)
    {
        if (currentStatus == TaskStatus.Completed)
            return (false, "Completed tasks cannot be modified");

        if (currentStatus == TaskStatus.Cancelled)
            return (false, "Cancelled tasks cannot be modified");

        if (currentStatus == TaskStatus.OnHold)
            return (false, "On Hold tasks must be resumed before status changes");

        var allowedTransitions = new Dictionary<(TaskStatus, UserRole), TaskStatus[]>
        {
            { (TaskStatus.NotStarted, UserRole.Dispatcher), new[] { TaskStatus.InProgress } },
            { (TaskStatus.NotStarted, UserRole.Encoder), new[] { TaskStatus.InProgress } },
            { (TaskStatus.NotStarted, UserRole.Courier), new[] { TaskStatus.InProgress } },

            { (TaskStatus.InProgress, UserRole.Dispatcher), new[] { TaskStatus.DonePendingReview } },
            { (TaskStatus.InProgress, UserRole.Encoder), new[] { TaskStatus.DonePendingReview } },
            { (TaskStatus.InProgress, UserRole.Courier), new[] { TaskStatus.DonePendingReview } },

            { (TaskStatus.DonePendingReview, UserRole.Coordinator), new[] { TaskStatus.Completed } },
            { (TaskStatus.DonePendingReview, UserRole.Manager), new[] { TaskStatus.Completed } },
        };

        var key = (currentStatus, user.Role);
        if (!allowedTransitions.ContainsKey(key))
        {
            return (false, $"Invalid status transition from {currentStatus} for role {user.Role}");
        }

        var allowedNextStates = allowedTransitions[key];
        if (!allowedNextStates.Contains(newStatus))
        {
            return (false, $"Status sequence violation - cannot transition from {currentStatus} to {newStatus}");
        }

        if (currentStatus == TaskStatus.NotStarted || currentStatus == TaskStatus.InProgress)
        {
            var isAssigned = task.Assignments.Any(a => a.AssignedUserId == userId);
            if (!isAssigned)
                return (false, "You are not the assigned employee for this task");
        }

        return (true, null);
    }

    private async Task<TaskResponseDTO> MapToResponseDTOAsync(Models.Task task)
    {
        await _db.Entry(task).Reference(t => t.CreatedBy).LoadAsync();
        await _db.Entry(task).Reference(t => t.AssignedDepartment).LoadAsync();
        await _db.Entry(task).Collection(t => t.Assignments).LoadAsync();

        foreach (var assignment in task.Assignments)
        {
            await _db.Entry(assignment).Reference(a => a.AssignedUser).LoadAsync();
        }

        return new TaskResponseDTO
        {
            Id = task.Id,
            Title = task.Title,
            Description = task.Description,
            PriorityLevel = task.PriorityLevel,
            Classification = task.Classification,
            Status = task.Status,
            AssignmentScope = task.AssignmentScope,
            Deadline = task.Deadline,
            IsSLALocked = task.IsSLALocked,
            IsConfidential = task.IsConfidential,
            CreatedById = task.CreatedById,
            CreatedByName = task.CreatedBy is not null
                ? $"{task.CreatedBy.FirstName} {task.CreatedBy.LastName}".Trim()
                : null,
            AssignedDepartmentId = task.AssignedDepartmentId,
            AssignedDepartmentName = task.AssignedDepartment?.Name,
            Assignees = task.Assignments.Select(a => new TaskAssigneeDTO
            {
                UserId = a.AssignedUserId,
                FullName = a.AssignedUser is not null
                    ? $"{a.AssignedUser.FirstName} {a.AssignedUser.MiddleName} {a.AssignedUser.LastName} {a.AssignedUser.Suffix}"
                        .Replace("  ", " ").Trim()
                    : "Unknown",
                EmployeeNumber = a.AssignedUser?.EmployeeNumber ?? "",
                Role = a.AssignedUser?.Role.ToString()
            }).ToList(),
            AttachmentCount = task.Attachments?.Count ?? 0,
            CreatedAt = task.CreatedAt,
            UpdatedAt = task.UpdatedAt
        };
    }
```

```csharp
    private (bool IsValid, string? ErrorMessage) ValidateTransition(

        if (currentStatus == TaskStatus.Cancelled)
            return (false, "Cancelled tasks cannot be modified");

        if (currentStatus == TaskStatus.OnHold)
            return (false, "On Hold tasks must be resumed before status changes");

        var allowedTransitions = new Dictionary<(TaskStatus, UserRole), TaskStatus[]>
        {
```
