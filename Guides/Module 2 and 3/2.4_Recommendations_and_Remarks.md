# Sub-Module 2.4: Recommendations & Remarks

## Functional Requirements Covered

| FR ID | Requirement Name | Description | Priority |
|-------|------------------|-------------|----------|
| FR-030 | Recommendations Input Field | Only Coordinators can add structured recommendations (category + notes) to task profiles. | High |
| FR-031 | Evaluation Archiving | Recommendations are automatically archived to the assignee's profile as read-only chronological history for monthly reviews. | High |
| FR-032 | Task Comments Thread | Authorized users can add, edit, and delete comments on tasks. Comments are displayed chronologically with optional file attachments. | High |

---

## 1. High-Level Pseudocode

### What We're Building

We need to create a system where:
1. Coordinators can add structured recommendations to tasks (category + notes, not just free text)
2. When a recommendation is saved, it's automatically copied to the assignee's profile as a permanent, read-only record
3. Managers and Coordinators can view an employee's full recommendation history (chronological) for monthly reviews
4. Any authorized user can add comments to tasks they have access to
5. Users can edit and delete their own comments (but not others')
6. Comments can optionally include file attachments
7. Comments are displayed in chronological order with author and timestamp

## 2. High-Level Explanation of Concepts

### Concept 1: Structured Recommendations (What it is)

A **Structured Recommendation** is a formal evaluation entry that has two parts: a Category (what aspect of work is being evaluated) and Notes (the actual feedback). This is different from free-text comments because it's organized and easy to filter/search.

**Why we use it:**
- Consistency - all recommendations follow the same format
- Easy to review - Managers can filter by category (e.g., "show all Work Quality recommendations")
- Fair evaluation - structured format reduces bias
- Audit trail - clear record of who said what and when

**How it works:**
```
RECOMMENDATION FORM:
{
  TaskId: "task-123",
  AssigneeId: "user-john", (auto-filled from task assignment)
  Category: WorkQuality, (dropdown: Timeliness, WorkQuality, Communication, Other)
  Notes: "John consistently produces accurate work with minimal errors." (text area)
}

CATEGORIES:
├── Timeliness → Did they finish on time?
├── WorkQuality → How good was the work?
├── Communication → Did they communicate well?
└── Other → Anything else worth noting

WHAT HAPPENS WHEN SAVED:
1. Recommendation is saved to the Task (linked to the task)
2. Recommendation is ALSO saved to the Assignee's profile (auto-archived)
3. Both records are permanent and read-only (can't be edited or deleted)
4. Manager can later view John's full recommendation history for monthly review
```

**Alternatives:**
- **Free-text comments**: No structure. Hard to organize and filter.
- **Star ratings (1-5)**: Too simplistic. Doesn't capture nuance.
- **Performance review forms**: Too complex for quick feedback.

**Common Mistakes:**
- Allowing recommendations to be edited or deleted (defeats the purpose of archiving)
- Not linking to both the task AND the assignee (need both for different views)
- Not requiring both category and notes (incomplete recommendations)
- Not checking that the user is a Coordinator (only they should recommend)

---

### Concept 2: Evaluation Archiving (What it is)

**Evaluation Archiving** means that when a Coordinator writes a recommendation, it's automatically saved to the assignee's profile as a permanent, read-only record. This creates a chronological history of all feedback an employee has received.

**Why we use it:**
- Monthly reviews - Managers need evidence of performance over time
- Fairness - employees can see their full history (no surprises)
- Accountability - Coordinators know their feedback is permanent
- Compliance - read-only ensures data integrity

**How it works:**
```
ARCHIVING FLOW:

1. Coordinator writes recommendation for John about Task #123
2. System saves recommendation to Task #123 (task view)
3. System ALSO saves recommendation to John's profile (employee view)
4. Both records point to the same data (same Recommendation record)

VIEWING HISTORY:
- Manager goes to John's profile
- Clicks "Recommendation History"
- System shows ALL recommendations for John, sorted by date:
  ├── Jan 15: WorkQuality - "Excellent attention to detail"
  ├── Jan 20: Timeliness - "Completed task ahead of schedule"
  ├── Feb 1: Communication - "Needs to update status more frequently"
  └── Feb 10: WorkQuality - "Consistent quality across all tasks"
- Manager uses this as evidence during monthly review

READ-ONLY:
- No one can edit or delete archived recommendations
- Not even the Coordinator who wrote it
- Not even the Manager
- This ensures the historical record is trustworthy
```

**Key Rules:**
- Recommendations are automatically archived (no manual step needed)
- Archived recommendations are read-only (no edit, no delete)
- History is chronological (oldest first or newest first)
- Only Managers and Coordinators can view the history

**Common Mistakes:**
- Allowing edits to archived recommendations (breaks the audit trail)
- Not auto-archiving (requires manual step, easy to forget)
- Not filtering by date range (history gets too long)
- Not showing the task reference (need to know which task the recommendation is about)

### Concept 3: Task Comments Thread (What it is)

A **Task Comments Thread** is a chronological conversation attached to a task. It's like a chat room for a specific task where authorized users can discuss, ask questions, share updates, and attach files.

**Why we use it:**
- Communication - team members can discuss the task without email
- Context - all discussion is linked to the task (not scattered in emails)
- Accountability - comments show who said what and when
- Flexibility - comments can be edited or deleted (unlike recommendations)

**How it works:**
```
COMMENT THREAD:

Task: "Daily Parcel Sorting"
┌─────────────────────────────────────────────────────────┐
│ John Doe (Encoder) - Jan 15, 10:30 AM                  │
│ "I've started sorting the parcels. Will update when    │
│  done."                                                 │
├─────────────────────────────────────────────────────────┤
│ Jane Smith (Coordinator) - Jan 15, 11:00 AM            │
│ "Great! Please prioritize Zone A parcels - they're     │
│  urgent."                                               │
│ 📎 priority_zones.pdf (245 KB)                         │
├─────────────────────────────────────────────────────────┤
│ John Doe (Encoder) - Jan 15, 2:00 PM                   │
│ "Zone A is done. Moving to Zone B now."                │
└─────────────────────────────────────────────────────────┘

FEATURES:
- Chronological order (oldest at top, newest at bottom)
- Shows author name and timestamp
- Optional file attachments
- Users can edit their own comments
- Users can delete their own comments (soft delete - hidden from thread)
- All actions are recorded in audit log
```

**Key Rules:**
- Only users with access to the task can view/add comments
- Users can only edit/delete their OWN comments
- Deleted comments are hidden (soft delete, not hard delete)
- Comments are chronological with author and timestamp
- File attachments are optional (max 20MB, same types as task attachments)

**Alternatives:**
- **Email threads**: Scattered, hard to link to specific tasks.
- **Chat apps (Slack/Teams)**: Separate from the task. Context is lost.
- **Notes field on task**: Only one person can edit. No conversation.

**Common Mistakes:**
- Not checking task access before showing comments (security issue)
- Allowing users to edit/delete others' comments (violates ownership)
- Hard deleting comments (loses audit trail)
- Not notifying task members of new comments

---

### Concept 4: Soft Delete for Comments (What it is)

**Soft Delete** for comments means marking a comment as "deleted" without actually removing it from the database. The comment is hidden from the thread but preserved for audit purposes.

**Why we use it:**
- Audit trail - we need to know what was said, even if deleted
- Compliance - legal requirements may mandate preserving all communications
- Recovery - if deleted by mistake, it can be restored (by admin)
- Data integrity - foreign key relationships aren't broken

**How it works:**
```
BEFORE DELETE:
Comment: { Id: 123, Content: "Some comment", IsDeleted: false }

AFTER DELETE:
Comment: { Id: 123, Content: "Some comment", IsDeleted: true }

IN THE UI:
- Comment is NOT shown in the thread (filtered out)
- But it still exists in the database
- Audit log records: "User X deleted comment #123 at [timestamp]"

DATABASE QUERY:
// Show comments (excluding deleted):
SELECT * FROM TaskComments WHERE TaskId = '...' AND IsDeleted = false

// Show ALL comments (including deleted, for audit):
SELECT * FROM TaskComments WHERE TaskId = '...'
```

**Alternatives:**
- **Hard delete**: Remove the record completely. Loses audit trail.
- **Move to archive table**: More complex, not needed.
- **Version history**: Keep all versions. Overkill for comments.

**Common Mistakes:**
- Forgetting to filter out deleted comments in queries
- Not recording the deletion in the audit log
- Allowing users to see their own deleted comments (confusing)
- Not handling attachments when deleting (orphan files)

---

### Concept 5: Comment Ownership (What it is)

**Comment Ownership** means each comment belongs to the user who created it. Only the owner can edit or delete their own comments. This prevents users from modifying others' statements.

**Why we use it:**
- Accountability - people are responsible for what they say
- Integrity - others' comments can't be changed
- Trust - users know their words won't be altered by others
- Simplicity - clear rule: "you own your comments"

**How it works:**
```
COMMENT: { Id: 123, AuthorId: "john-id", Content: "I'll finish by 3 PM" }

JOHN tries to edit:
- System checks: "Is John the author?" → Yes → Allow edit

JANE tries to edit John's comment:
- System checks: "Is Jane the author?" → No → Deny with error:
  "Unauthorized comment modification"

MANAGER tries to delete John's comment:
- System checks: "Is Manager the author?" → No → Deny
- Even Managers can't delete others' comments (only their own)
```

**Key Rules:**
- Only the author can edit their comments
- Only the author can delete their comments
- No exceptions (not even Managers or Coordinators)
- Attempting to modify others' comments returns an error

**Common Mistakes:**
- Not checking ownership before allowing edit/delete
- Allowing Managers to override ownership (breaks trust)
- Not returning a clear error message ("Unauthorized comment modification")
- Not checking ownership on the backend (frontend-only check is insecure)

**File: `backend/Modules/TaskManagement/RecommendationService.cs`**

```csharp
using Microsoft.EntityFrameworkCore;
using Backend.Data;
using Backend.Models;
using Backend.Models.DTOs;
using Backend.Models.Enums;

namespace Backend.Modules.TaskManagement;

public class RecommendationService : IRecommendationService
{
    private readonly AppDbContext _db;

    public RecommendationService(AppDbContext db)
    {
        _db = db;
    }

    public async Task<ApiResponseDTO<RecommendationResponseDTO>> CreateAsync(
        Guid taskId, CreateRecommendationDTO dto, Guid coordinatorId)
    {
        var coordinator = await _db.Users.FindAsync(coordinatorId);
        if (coordinator is null)
            return ApiResponseDTO<RecommendationResponseDTO>.Failure("User not found");

        if (coordinator.Role != UserRole.Coordinator && coordinator.Role != UserRole.Manager)
            return ApiResponseDTO<RecommendationResponseDTO>.Failure(
                "Only Coordinators and Managers can add recommendations");

        var task = await _db.Tasks
            .Include(t => t.Assignments)
            .FirstOrDefaultAsync(t => t.Id == taskId);

        if (task is null)
            return ApiResponseDTO<RecommendationResponseDTO>.Failure("Task not found");

        if (string.IsNullOrWhiteSpace(dto.Notes))
            return ApiResponseDTO<RecommendationResponseDTO>.Failure("Recommendation notes are required");

        var assigneeId = task.Assignments.FirstOrDefault()?.AssignedUserId;
        if (!assigneeId.HasValue)
            return ApiResponseDTO<RecommendationResponseDTO>.Failure(
                "Task has no assigned user to recommend");

        var recommendation = new Recommendation
        {
            TaskId = taskId,
            AssigneeId = assigneeId.Value,
            CoordinatorId = coordinatorId,
            Category = dto.Category,
            Notes = dto.Notes.Trim(),
            CreatedAt = DateTime.UtcNow
        };

        _db.Recommendations.Add(recommendation);
        await _db.SaveChangesAsync();

        return ApiResponseDTO<RecommendationResponseDTO>.Success(
            await MapToResponseDTOAsync(recommendation),
            "Recommendation saved successfully");
    }

    public async Task<ApiResponseDTO<List<RecommendationResponseDTO>>> GetByTaskIdAsync(Guid taskId)
    {
        var taskExists = await _db.Tasks.AnyAsync(t => t.Id == taskId);
        if (!taskExists)
            return ApiResponseDTO<List<RecommendationResponseDTO>>.Failure("Task not found");

        var recommendations = await _db.Recommendations
            .Include(r => r.Task)
            .Include(r => r.Assignee)
            .Include(r => r.Coordinator)
            .Where(r => r.TaskId == taskId)
            .OrderByDescending(r => r.CreatedAt)
            .ToListAsync();

        var response = new List<RecommendationResponseDTO>();
        foreach (var rec in recommendations)
        {
            response.Add(await MapToResponseDTOAsync(rec));
        }

        return ApiResponseDTO<List<RecommendationResponseDTO>>.Success(response);
    }

    public async Task<ApiResponseDTO<List<RecommendationResponseDTO>>> GetByAssigneeIdAsync(
        Guid assigneeId, DateTime? dateFrom = null, DateTime? dateTo = null)
    {
        var query = _db.Recommendations
            .Include(r => r.Task)
            .Include(r => r.Assignee)
            .Include(r => r.Coordinator)
            .Where(r => r.AssigneeId == assigneeId)
            .AsQueryable();

        if (dateFrom.HasValue)
            query = query.Where(r => r.CreatedAt >= dateFrom.Value);

        if (dateTo.HasValue)
            query = query.Where(r => r.CreatedAt <= dateTo.Value);

        var recommendations = await query
            .OrderBy(r => r.CreatedAt)
            .ToListAsync();

        var response = new List<RecommendationResponseDTO>();
        foreach (var rec in recommendations)
        {
            response.Add(await MapToResponseDTOAsync(rec));
        }

        return ApiResponseDTO<List<RecommendationResponseDTO>>.Success(response);
    }

    private async Task<RecommendationResponseDTO> MapToResponseDTOAsync(Recommendation rec)
    {
        return new RecommendationResponseDTO
        {
            Id = rec.Id,
            TaskId = rec.TaskId,
            TaskTitle = rec.Task?.Title,
            AssigneeId = rec.AssigneeId,
            AssigneeName = rec.Assignee is not null
                ? $"{rec.Assignee.FirstName} {rec.Assignee.LastName}".Trim()
                : null,
            CoordinatorId = rec.CoordinatorId,
            CoordinatorName = rec.Coordinator is not null
                ? $"{rec.Coordinator.FirstName} {rec.Coordinator.LastName}".Trim()
                : null,
            Category = rec.Category,
            Notes = rec.Notes,
            CreatedAt = rec.CreatedAt
        };
    }
}
```

```csharp
using Microsoft.EntityFrameworkCore;
using Backend.Data;
using Backend.Models;
using Backend.Models.DTOs;
using Microsoft.Extensions.Options;

namespace Backend.Modules.TaskManagement;

public class TaskCommentService : ITaskCommentService
{
    private readonly AppDbContext _db;
    private readonly FileStorageSettings _fileSettings;
    private readonly ILogger<TaskCommentService> _logger;

    public TaskCommentService(
        AppDbContext db,
        IOptions<FileStorageSettings> fileSettings,
        ILogger<TaskCommentService> logger)
    {
        _db = db;
        _fileSettings = fileSettings.Value;
        _logger = logger;
    }

    public async Task<ApiResponseDTO<TaskCommentResponseDTO>> CreateAsync(
        Guid taskId, string content, IFormFile? file, Guid authorId)
    {
        var taskExists = await _db.Tasks.AnyAsync(t => t.Id == taskId);
        if (!taskExists)
            return ApiResponseDTO<TaskCommentResponseDTO>.Failure("Task not found");

        var author = await _db.Users.FindAsync(authorId);
        if (author is null)
            return ApiResponseDTO<TaskCommentResponseDTO>.Failure("User not found");

        if (string.IsNullOrWhiteSpace(content))
            return ApiResponseDTO<TaskCommentResponseDTO>.Failure("Comment content is required");

        var comment = new TaskComment
        {
            TaskId = taskId,
            AuthorId = authorId,
            Content = content.Trim(),
            CreatedAt = DateTime.UtcNow
        };

        if (file is not null && file.Length > 0)
        {
            var extension = Path.GetExtension(file.FileName).ToLower();
            if (!_fileSettings.AllowedFileTypes.Contains(extension))
                return ApiResponseDTO<TaskCommentResponseDTO>.Failure(
                    $"Unsupported file format. Allowed: {string.Join(", ", _fileSettings.AllowedFileTypes)}");

            if (file.Length > _fileSettings.MaxFileSizeBytes)
                return ApiResponseDTO<TaskCommentResponseDTO>.Failure(
                    $"File exceeds the maximum allowed size ({_fileSettings.MaxFileSizeBytes / 1024 / 1024}MB)");

            var uploadDir = Path.Combine(Directory.GetCurrentDirectory(),
                _fileSettings.UploadPath, "comments", taskId.ToString());

            if (!Directory.Exists(uploadDir))
                Directory.CreateDirectory(uploadDir);

            var uniqueFileName = $"{Guid.NewGuid()}{extension}";
            var filePath = Path.Combine(uploadDir, uniqueFileName);

            using (var stream = new FileStream(filePath, FileMode.Create))
            {
                await file.CopyToAsync(stream);
            }

            comment.AttachmentFilePath = filePath;
            comment.AttachmentFileName = file.FileName;
        }

        _db.TaskComments.Add(comment);
        await _db.SaveChangesAsync();

        return ApiResponseDTO<TaskCommentResponseDTO>.Success(
            await MapToResponseDTOAsync(comment),
            "Comment added successfully");
    }

    public async Task<ApiResponseDTO<List<TaskCommentResponseDTO>>> GetByTaskIdAsync(Guid taskId)
    {
        var taskExists = await _db.Tasks.AnyAsync(t => t.Id == taskId);
        if (!taskExists)
            return ApiResponseDTO<List<TaskCommentResponseDTO>>.Failure("Task not found");

        var comments = await _db.TaskComments
            .Include(c => c.Author)
            .Where(c => c.TaskId == taskId && !c.IsDeleted)
            .OrderBy(c => c.CreatedAt)
            .ToListAsync();

        var response = new List<TaskCommentResponseDTO>();
        foreach (var comment in comments)
        {
            response.Add(await MapToResponseDTOAsync(comment));
        }

        return ApiResponseDTO<List<TaskCommentResponseDTO>>.Success(response);
    }

    public async Task<ApiResponseDTO<TaskCommentResponseDTO>> UpdateAsync(
        Guid commentId, string newContent, Guid userId)
    {
        var comment = await _db.TaskComments.FindAsync(commentId);
        if (comment is null)
            return ApiResponseDTO<TaskCommentResponseDTO>.Failure("Comment not found");

        if (comment.IsDeleted)
            return ApiResponseDTO<TaskCommentResponseDTO>.Failure("Cannot edit a deleted comment");

        if (comment.AuthorId != userId)
            return ApiResponseDTO<TaskCommentResponseDTO>.Failure("Unauthorized comment modification");

        if (string.IsNullOrWhiteSpace(newContent))
            return ApiResponseDTO<TaskCommentResponseDTO>.Failure("Comment content is required");

        comment.Content = newContent.Trim();
        comment.UpdatedAt = DateTime.UtcNow;
        await _db.SaveChangesAsync();

        return ApiResponseDTO<TaskCommentResponseDTO>.Success(
            await MapToResponseDTOAsync(comment),
            "Comment updated successfully");
    }

    public async Task<ApiResponseDTO<bool>> DeleteAsync(Guid commentId, Guid userId)
    {
        var comment = await _db.TaskComments.FindAsync(commentId);
        if (comment is null)
            return ApiResponseDTO<bool>.Failure("Comment not found");

        if (comment.AuthorId != userId)
            return ApiResponseDTO<bool>.Failure("Unauthorized comment modification");

        comment.IsDeleted = true;
        comment.UpdatedAt = DateTime.UtcNow;
        await _db.SaveChangesAsync();

        return ApiResponseDTO<bool>.Success(true, "Comment deleted successfully");
    }

    private async Task<TaskCommentResponseDTO> MapToResponseDTOAsync(TaskComment comment)
    {
        await _db.Entry(comment).Reference(c => c.Author).LoadAsync();

        return new TaskCommentResponseDTO
        {
            Id = comment.Id,
            TaskId = comment.TaskId,
            AuthorId = comment.AuthorId,
            AuthorName = comment.Author is not null
                ? $"{comment.Author.FirstName} {comment.Author.LastName}".Trim()
                : "Unknown",
            Content = comment.Content,
            AttachmentFileName = comment.AttachmentFileName,
            IsDeleted = comment.IsDeleted,
            CreatedAt = comment.CreatedAt,
            UpdatedAt = comment.UpdatedAt
        };
    }
}
```
