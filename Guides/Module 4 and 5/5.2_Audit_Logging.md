# Sub-Module 5.2: Audit Logging

## Functional Requirements Covered

| FR ID | Requirement Name | Description | Priority |
|-------|------------------|-------------|----------|
| FR-046 | Event Logging | The system shall log every login/logout, task status change, edit to task/user/config records, and file upload. Logging occurs automatically. If audit log write fails, the triggering action shall not silently proceed unlogged. | High |
| FR-047 | Audit Log Structure | Every audit entry shall record: User ID, Action Type, Timestamp, Affected Record, and IP Address. Update actions shall additionally capture Old Value and New Value. Timestamps shall be exact. Structure consistent across all modules. | High |
| FR-048 | Manager Log View Boundary | Only the Manager shall be allowed to view the Audit Log module. Audit Log entries shall be filterable by date range, user, action type, and target module. Every access (authorized or denied) shall itself be logged. | High |
| FR-049 | Audit Log Immutability | No user, including the Manager, shall be able to edit, delete, or export raw audit log entries. Every attempted modification shall be blocked and itself logged. | High |

---

## 1. High-Level Pseudocode

### What We're Building

We need to create a system where:
1. Every loggable action (login, logout, task status change, record edit, file upload) automatically creates an audit log entry
2. Each audit entry captures: User ID, Action Type, Timestamp, Affected Record/Entity, IP Address, and Old/New Values (for updates)
3. Only the Manager can view audit logs, with filtering by date range, user, action type, and target module
4. Every access to the audit log (authorized or denied) is itself logged as a meta-entry
5. Audit log entries are immutable — no edit, delete, or export is allowed
6. Any attempt to modify audit entries is blocked and logged

### Step-by-Step Logic

```
STEP 1: Create AuditActionType Enum
├── Login → user logged in
├── Logout → user logged out
├── Create → new record created (task, user, etc.)
├── Read → record viewed (used for audit log access meta-logging)
├── Update → record modified (captures old/new values)
├── Delete → record removed
├── StatusChange → task status transition
├── Upload → file uploaded
├── Export → report exported
├── AccessDenied → unauthorized access attempt
└── BlockedAction → blocked modification attempt (e.g., trying to delete audit log)

STEP 2: Create AuditLog Model (the database table)
├── Id (auto-generated GUID)
├── UserId (who performed the action — nullable for anonymous attempts)
├── ActionType (enum from Step 1)
├── Timestamp (exact DateTime.UtcNow)
├── TargetEntity (what was affected: "Task", "User", "AuditLog", etc.)
├── TargetEntityId (the GUID of the affected record)
├── IpAddress (request IP address)
├── OldValue (JSON string — what the record looked like before, for updates)
├── NewValue (JSON string — what the record looks like after, for updates)
├── Description (human-readable summary of the action)
└── Module (which module triggered this: "Authentication", "TaskManagement", "AuditLog", etc.)

STEP 3: Create AuditLog DTOs
├── AuditLogResponseDTO → output for displaying audit log data
├── AuditLogFilterDTO → input for filtering (date range, user, action type, module)
└── AuditLogMetaDTO → summary data (total count, recent entries)

STEP 4: Create IAuditLogService
├── LogAsync(userId, actionType, targetEntity, targetEntityId, ipAddress, description, module, oldValue, newValue) → create audit entry
├── GetAllAsync(filters) → retrieve filtered audit logs (Manager only)
├── GetByIdAsync(id) → retrieve single entry (Manager only)
├── BlockModificationAsync(attemptedAction, targetEntityId, userId, ipAddress) → log blocked attempt
└── LogAccessAsync(userId, ipAddress) → meta-log for audit log access

STEP 5: Create AuditLogService (the "brain" for audit logic)
├── LogAsync → validate required fields, create entry, save to database
├── GetAllAsync → apply filters, return sorted by timestamp descending
├── GetByIdAsync → return single entry
├── BlockModificationAsync → create entry with ActionType = BlockedAction
└── LogAccessAsync → create entry with ActionType = Read, TargetEntity = "AuditLog"

STEP 6: Create AuditLogController (the "door" for HTTP requests)
├── GET /api/audit-logs → get all audit logs with filters (Manager only)
├── GET /api/audit-logs/{id} → get single audit log (Manager only)
├── GET /api/audit-logs/meta → get summary/meta data (Manager only)
├── PUT /api/audit-logs/{id} → BLOCKED — returns 403 + logs the attempt
├── DELETE /api/audit-logs/{id} → BLOCKED — returns 403 + logs the attempt
└── POST /api/audit-logs/{id}/export → BLOCKED — returns 403 + logs the attempt

STEP 7: Create AuditLogMiddleware (automatic logging for requests)
├── Intercept requests to detect loggable actions
├── Capture IP address from HttpContext
├── Provide IAuditLogService via DI for manual logging in services
└── Note: Most logging is done manually in services (not middleware) for precision

STEP 8: Integrate Audit Logging into Existing Services
├── AuthService → log Login and Logout events
├── TaskService → log Create, Update, StatusChange events
├── TaskWorkflowService → log StatusChange events
├── AttachmentService → log Upload events
├── UserService → log Create, Update, Deactivate events
└── ReportService → log Export events

STEP 9: Update AppDbContext.cs
├── Add DbSet<AuditLog>
└── Configure AuditLog entity (indexes, constraints)

STEP 10: Update Program.cs
├── Register AuditLogService
└── No additional configuration needed

STEP 11: Create Database Migration
└── Add AuditLogs table
```

## 2. High-Level Explanation of Concepts

### Concept 1: Audit Log Entry Structure (What it is)

**Audit Log Entry Structure** defines the mandatory fields that every audit log record must contain. This ensures consistency across all modules — whether a login event or a task edit, the structure is the same.

**Why we use it:**
- Consistency: every entry has the same fields regardless of which module triggered it
- Traceability: you can always trace who did what, when, and from where
- Compliance: meets regulatory requirements for audit trails
- Investigation: enables forensic analysis when something goes wrong

**How it works:**
```
REQUIRED FIELDS (every entry):
├── Id → unique identifier (GUID)
├── UserId → who performed the action (nullable for anonymous attempts)
├── ActionType → what type of action (Login, Create, Update, etc.)
├── Timestamp → exact date/time in UTC
├── TargetEntity → what was affected ("Task", "User", "AuditLog", etc.)
├── TargetEntityId → GUID of the affected record (nullable for Login/Logout)
├── IpAddress → where the request came from
├── Description → human-readable summary
└── Module → which module triggered this

CONDITIONAL FIELDS (for Update actions):
├── OldValue → JSON string of the record before the change
└── NewValue → JSON string of the record after the change

EXAMPLE ENTRIES:

Login Event:
{
  id: "guid-1",
  userId: "user-guid",
  actionType: "Login",
  timestamp: "2026-07-13T12:00:00Z",
  targetEntity: "User",
  targetEntityId: "user-guid",
  ipAddress: "192.168.1.100",
  description: "User john.doe logged in",
  module: "Authentication",
  oldValue: null,
  newValue: null
}

Task Status Change:
{
  id: "guid-2",
  userId: "user-guid",
  actionType: "StatusChange",
  timestamp: "2026-07-13T12:30:00Z",
  targetEntity: "Task",
  targetEntityId: "task-guid",
  ipAddress: "192.168.1.100",
  description: "Task status changed from InProgress to Completed",
  module: "TaskManagement",
  oldValue: "InProgress",
  newValue: "Completed"
}

Task Edit (with old/new values):
{
  id: "guid-3",
  userId: "user-guid",
  actionType: "Update",
  timestamp: "2026-07-13T13:00:00Z",
  targetEntity: "Task",
  targetEntityId: "task-guid",
  ipAddress: "192.168.1.100",
  description: "Task title updated",
  module: "TaskManagement",
  oldValue: "{\"Title\": \"Sort parcels\"}",
  newValue: "{\"Title\": \"Sort morning parcels\"}"
}
```

**Common Mistakes:**
- Not capturing IP address (loses forensic value)
- Using local time instead of UTC (timezone inconsistencies)
- Not including OldValue/NewValue for update actions
- Inconsistent TargetEntity naming ("task" vs "Task" vs "Tasks")
- Storing sensitive data in OldValue/NewValue (passwords, tokens)

### Concept 2: Audit Log Immutability (What it is)

**Audit Log Immutability** means once an audit log entry is created, it can NEVER be modified, deleted, or exported. This is enforced at the API level — any attempt to modify an audit entry is blocked and itself logged.

**Why we use it:**
- Integrity: audit logs must be trustworthy — if they can be modified, they're useless
- Compliance: regulations require immutable audit trails
- Accountability: even the Manager cannot tamper with logs
- Detection: blocked attempts are themselves logged, creating a record of tampering attempts

**How it works:**
```
IMMUTABILITY RULES:
1. NO PUT/PATCH on /api/audit-logs/{id} → blocked
2. NO DELETE on /api/audit-logs/{id} → blocked
3. NO POST /api/audit-logs/{id}/export → blocked
4. Only GET (read) is allowed

BLOCKED ATTEMPT FLOW:
1. User (even Manager) sends PUT /api/audit-logs/{id}
2. Controller detects the action is not GET
3. Controller returns 403 Forbidden with message:
   "Audit records are immutable and cannot be edited, deleted, or exported."
4. Controller calls _auditLogService.BlockModificationAsync():
   ├── ActionType = BlockedAction
   ├── Description = "Attempted to edit audit log entry {id}"
   ├── TargetEntity = "AuditLog"
   └── TargetEntityId = the audit log entry's ID
5. The blocked attempt is now itself an audit log entry

WHY THIS WORKS:
- The immutability is enforced at the controller level (API gateway)
- Even if someone bypasses the API and writes directly to the database,
  the application layer never exposes mutation endpoints
- Database-level protection could be added with read-only table permissions
  (but that's a deployment concern, not a code concern)
```

**Alternatives:**
- **Database-level immutability**: Make the table read-only at the DB level. Stronger but harder to manage.
- **Append-only storage**: Use an append-only database or event store. Overkill for this scale.
- **Soft delete**: Mark entries as "deleted" but keep them. Doesn't meet immutability requirement.
- **Encryption + signing**: Cryptographically sign each entry. More secure but complex.

**Common Mistakes:**
- Exposing PUT/DELETE endpoints even with authorization checks (shouldn't exist at all)
- Not logging the blocked attempt (loses the tampering record)
- Allowing batch delete (could wipe all logs at once)
- Not protecting the export endpoint (raw data leak)

### Concept 3: Meta-Logging (Audit Log Access Logging) (What it is)

**Meta-Logging** is the practice of logging every access to the audit log itself. When a Manager views the audit log, that view is recorded as its own audit entry. When someone unauthorized tries to view it, that attempt is also recorded.

**Why we use it:**
- Accountability: who viewed the audit log and when?
- Detection: unauthorized access attempts are visible
- Compliance: some regulations require logging of audit log access
- Forensics: if logs are tampered with, meta-logs show who accessed them

**How it works:**
```
AUTHORIZED ACCESS:
1. Manager sends GET /api/audit-logs
2. Controller validates: role = Manager → allowed
3. Controller calls _auditLogService.LogAccessAsync(userId, ipAddress)
4. Audit entry created:
   ├── ActionType = Read
   ├── TargetEntity = "AuditLog"
   ├── Description = "Manager {name} accessed audit log"
   └── Module = "AuditLog"
5. Audit log data returned to Manager

UNAUTHORIZED ACCESS:
1. Encoder sends GET /api/audit-logs
2. Authorization policy blocks: returns 403
3. Controller (or middleware) calls _auditLogService.LogAccessAttemptAsync():
   ├── ActionType = AccessDenied
   ├── TargetEntity = "AuditLog"
   ├── Description = "Unauthorized access attempt to audit log by {name}"
   └── Module = "AuditLog"
4. 403 returned to Encoder (no log data revealed)

IMPORTANT: The meta-log entry itself is immutable and cannot be deleted.
This creates a chain of accountability for audit log access.
```

**Common Mistakes:**
- Not logging unauthorized access attempts (loses detection capability)
- Revealing audit log contents in the denial message (information leak)
- Not logging the IP address of the access attempt
- Logging successful access but not failed attempts (or vice versa)

### Concept 4: IP Address Capture (What it is)

**IP Address Capture** records the originating IP address of every request that triggers an audit log entry. This is extracted from the HTTP request context.

**Why we use it:**
- Forensics: identify where an action originated from
- Security: detect suspicious access from unexpected locations
- Compliance: many regulations require IP address logging
- Investigation: correlate actions across systems by IP

**How it works:**
```
IP ADDRESS EXTRACTION:
1. Get IP from HttpContext.Connection.RemoteIpAddress
2. If behind a proxy/load balancer:
   ├── Check X-Forwarded-For header (first IP in the list)
   ├── Check X-Real-IP header
   └── Fall back to RemoteIpAddress
3. Store as string in the audit log entry

EXAMPLE:
Direct connection: "192.168.1.100"
Behind proxy: "203.0.113.50" (from X-Forwarded-For)
IPv6: "::1" (localhost) or "2001:db8::1"

IN ASP.NET CORE:
var ipAddress = HttpContext.Connection.RemoteIpAddress?.ToString();

// If behind a reverse proxy (like nginx):
var forwardedFor = HttpContext.Request.Headers["X-Forwarded-For"].FirstOrDefault();
if (!string.IsNullOrEmpty(forwardedFor))
    ipAddress = forwardedFor.Split(',').First().Trim();
```

**Common Mistakes:**
- Not handling proxy headers (gets proxy IP instead of real client IP)
- Not handling null IP addresses (localhost, testing)
- Storing IP as binary instead of string (harder to read in logs)
- Not considering IPv6 format

### Concept 5: Service-Level Audit Integration (What it is)

**Service-Level Audit Integration** means the audit logging calls are placed directly inside the service methods that perform the actions. This is more precise than middleware-based logging because we can capture exactly what changed (old/new values) and only log meaningful actions.

**Why we use it:**
- Precision: we know exactly what action occurred and what data changed
- Old/New values: only the service knows what the old values were before the update
- Conditional logging: we can skip logging for trivial operations
- Context: we have access to the full domain objects for rich descriptions

**How it works:**
```
INTEGRATION POINTS:

1. AuthService.LoginAsync():
   ├── After successful login → _auditLogService.LogAsync(
   │     userId, Login, "User", userId, ipAddress,
   │     "User {name} logged in", "Authentication")

2. TaskService.CreateAsync():
   ├── After task saved → _auditLogService.LogAsync(
   │     creatorId, Create, "Task", task.Id, ipAddress,
   │     "Task '{title}' created by {name}", "TaskManagement")

3. TaskWorkflowService.UpdateStatusAsync():
   ├── After status changed → _auditLogService.LogAsync(
   │     userId, StatusChange, "Task", taskId, ipAddress,
   │     "Task status changed from {old} to {new}", "TaskManagement",
   │     oldValue: oldStatus, newValue: newStatus)

4. TaskService.UpdateAsync():
   ├── Before save: capture old values
   ├── After save: capture new values
   └── _auditLogService.LogAsync(
         userId, Update, "Task", taskId, ipAddress,
         "Task updated", "TaskManagement",
         oldValue: JsonSerializer.Serialize(oldValues),
         newValue: JsonSerializer.Serialize(newValues))

5. AttachmentService.UploadAsync():
   ├── After attachment saved → _auditLogService.LogAsync(
   │     uploaderId, Upload, "TaskAttachment", attachment.Id, ipAddress,
   │     "File '{fileName}' uploaded to task {taskId}", "TaskManagement")

6. ReportService.ExportReportAsync():
   ├── After export → _auditLogService.LogAsync(
   │     userId, Export, "Report", Guid.Empty, ipAddress,
   │     "Performance report exported as {format}", "Reporting")

IP ADDRESS PASSING:
- Controller extracts IP from HttpContext
- Controller passes IP to service method
- Service passes IP to _auditLogService.LogAsync()
```

**Alternatives:**
- **Middleware-based logging**: Intercepts all requests automatically. Less precise, can't capture old/new values.
- **Event-driven (domain events)**: Services raise events, listeners create audit entries. More decoupled but complex.
- **AOP (Aspect-Oriented Programming)**: Decorators intercept method calls. Clean but harder to debug.
- **Database triggers**: Log at the database level. Misses business context (who, why).

**Common Mistakes:**
- Not passing IP address from controller to service (loses forensic data)
- Logging too much (every GET request) — only log meaningful actions
- Logging sensitive data in OldValue/NewValue (passwords, tokens)
- Not handling audit log write failures (should block the main action per FR-046)
- Creating circular dependencies (AuditLogService depending on TaskService)

### Step 5: Create AuditLogService

**File: `backend/Modules/TaskManagement/AuditLogService.cs`**

```csharp
using Microsoft.EntityFrameworkCore;
using Backend.Data;
using Backend.Models;
using Backend.Models.DTOs;
using Backend.Models.Enums;

namespace Backend.Modules.TaskManagement;

public class AuditLogService : IAuditLogService
{
    private readonly AppDbContext _db;
    private readonly ILogger<AuditLogService> _logger;

    public AuditLogService(AppDbContext db, ILogger<AuditLogService> logger)
    {
        _db = db;
        _logger = logger;
    }

    public async Task LogAsync(
        Guid? userId,
        AuditActionType actionType,
        string targetEntity,
        Guid? targetEntityId,
        string? ipAddress,
        string description,
        string module,
        string? oldValue = null,
        string? newValue = null)
    {
        try
        {
            var entry = new AuditLog
            {
                UserId = userId,
                ActionType = actionType,
                TargetEntity = targetEntity,
                TargetEntityId = targetEntityId,
                IpAddress = ipAddress,
                Description = description,
                Module = module,
                OldValue = oldValue,
                NewValue = newValue,
                Timestamp = DateTime.UtcNow
            };

            _db.AuditLogs.Add(entry);
            await _db.SaveChangesAsync();
        }
        catch (Exception ex)
        {
            _logger.LogError(ex, "Failed to write audit log entry. Action: {Action}, Entity: {Entity}, User: {User}",
                actionType, targetEntity, userId);

            throw new InvalidOperationException(
                "Audit log write failed — action blocked until logging succeeds.", ex);
        }
    }

    public async Task<ApiResponseDTO<List<AuditLogResponseDTO>>> GetAllAsync(AuditLogFilterDTO? filters = null)
    {
        var query = _db.AuditLogs
            .Include(a => a.User)
            .AsQueryable();

        if (filters != null)
        {
            if (filters.DateRangeStart.HasValue)
                query = query.Where(a => a.Timestamp >= filters.DateRangeStart.Value.ToUniversalTime());

            if (filters.DateRangeEnd.HasValue)
                query = query.Where(a => a.Timestamp <= filters.DateRangeEnd.Value.ToUniversalTime().Date.AddDays(1));

            if (filters.UserId.HasValue)
                query = query.Where(a => a.UserId == filters.UserId.Value);

            if (filters.ActionType.HasValue)
                query = query.Where(a => a.ActionType == filters.ActionType.Value);

            if (!string.IsNullOrWhiteSpace(filters.Module))
                query = query.Where(a => a.Module == filters.Module);

            if (!string.IsNullOrWhiteSpace(filters.TargetEntity))
                query = query.Where(a => a.TargetEntity == filters.TargetEntity);
        }

        var entries = await query
            .OrderByDescending(a => a.Timestamp)
            .ToListAsync();

        var response = entries.Select(MapToResponseDTO).ToList();
        return ApiResponseDTO<List<AuditLogResponseDTO>>.Success(response);
    }

    public async Task<ApiResponseDTO<AuditLogResponseDTO>> GetByIdAsync(Guid id)
    {
        var entry = await _db.AuditLogs
            .Include(a => a.User)
            .FirstOrDefaultAsync(a => a.Id == id);

        if (entry is null)
            return ApiResponseDTO<AuditLogResponseDTO>.Failure("Audit log entry not found.");

        return ApiResponseDTO<AuditLogResponseDTO>.Success(MapToResponseDTO(entry));
    }

    public async Task LogAccessAsync(Guid userId, string? ipAddress)
    {
        var user = await _db.Users.FindAsync(userId);
        var userName = user is not null
            ? $"{user.FirstName} {user.LastName}".Trim()
            : "Unknown";

        await LogAsync(
            userId,
            AuditActionType.Read,
            "AuditLog",
            null,
            ipAddress,
            $"Manager {userName} accessed audit log",
            "AuditLog");
    }

    public async Task LogAccessDeniedAsync(Guid? userId, string? ipAddress, string targetEntity)
    {
        string actorName;
        if (userId.HasValue)
        {
            var user = await _db.Users.FindAsync(userId.Value);
            actorName = user is not null
                ? $"{user.FirstName} {user.LastName}".Trim()
                : "Unknown";
        }
        else
        {
            actorName = "Anonymous";
        }

        await LogAsync(
            userId,
            AuditActionType.AccessDenied,
            targetEntity,
            null,
            ipAddress,
            $"Unauthorized access attempt to {targetEntity} by {actorName}",
            "AuditLog");
    }

    public async Task LogBlockedModificationAsync(
        Guid? userId,
        string? ipAddress,
        string attemptedAction,
        Guid? targetEntityId)
    {
        string actorName;
        if (userId.HasValue)
        {
            var user = await _db.Users.FindAsync(userId.Value);
            actorName = user is not null
                ? $"{user.FirstName} {user.LastName}".Trim()
                : "Unknown";
        }
        else
        {
            actorName = "Anonymous";
        }

        await LogAsync(
            userId,
            AuditActionType.BlockedAction,
            "AuditLog",
            targetEntityId,
            ipAddress,
            $"Blocked attempt by {actorName} to {attemptedAction} audit log entry",
            "AuditLog");
    }

    private AuditLogResponseDTO MapToResponseDTO(AuditLog entry)
    {
        return new AuditLogResponseDTO
        {
            Id = entry.Id,
            UserId = entry.UserId,
            ActorName = entry.User is not null
                ? $"{entry.User.FirstName} {entry.User.LastName}".Trim()
                : null,
            ActorRole = entry.User?.Role.ToString(),
            ActionType = entry.ActionType.ToString(),
            Timestamp = entry.Timestamp,
            TargetEntity = entry.TargetEntity,
            TargetEntityId = entry.TargetEntityId,
            IpAddress = entry.IpAddress,
            OldValue = entry.OldValue,
            NewValue = entry.NewValue,
            Description = entry.Description,
            Module = entry.Module
        };
    }
}
```

        [FromQuery] AuditActionType? actionType = null,

            await _auditLogService.LogAccessAsync(requestUserId.Value, ipAddress);

        {
            DateRangeStart = dateRangeStart,
            DateRangeEnd = dateRangeEnd,
            UserId = userId,
            ActionType = actionType,
            Module = module,
            TargetEntity = targetEntity
        };

        var result = await _auditLogService.GetAllAsync(filters);
        return Ok(result);
    }

    [HttpGet("{id:guid}")]
    [Authorize(Policy = AuthorizationPolicies.CanAccessAuditLogs)]
    public async Task<IActionResult> GetById(Guid id)
    {
        var requestUserId = GetUserIdFromClaims();
        var ipAddress = GetIpAddress();

        if (requestUserId.HasValue)
            await _auditLogService.LogAccessAsync(requestUserId.Value, ipAddress);

        var result = await _auditLogService.GetByIdAsync(id);
        if (!result.IsSuccess)
            return NotFound(result);

        return Ok(result);
    }

    [HttpPut("{id:guid}")]
    [Authorize(Policy = AuthorizationPolicies.CanAccessAuditLogs)]
    public async Task<IActionResult> AttemptUpdate(Guid id)
    {
        var requestUserId = GetUserIdFromClaims();
        var ipAddress = GetIpAddress();

        await _auditLogService.LogBlockedModificationAsync(
            requestUserId, ipAddress, "edit", id);

        return StatusCode(403, ApiResponseDTO<object>.Failure(
            "Audit records are immutable and cannot be edited, deleted, or exported."));
    }

    [HttpDelete("{id:guid}")]
    [Authorize(Policy = AuthorizationPolicies.CanAccessAuditLogs)]

    [Authorize(Policy = AuthorizationPolicies.CanAccessAuditLogs)]
    public async Task<IActionResult> AttemptExport(Guid id)
    {
        var requestUserId = GetUserIdFromClaims();
        var ipAddress = GetIpAddress();

        await _auditLogService.LogBlockedModificationAsync(
            requestUserId, ipAddress, "export", id);

        return StatusCode(403, ApiResponseDTO<object>.Failure(
            "Audit records are immutable and cannot be edited, deleted, or exported."));
    }

    private Guid? GetUserIdFromClaims()
    {
        var userId = User.FindFirst(ClaimTypes.NameIdentifier)?.Value;
        if (string.IsNullOrEmpty(userId) || !Guid.TryParse(userId, out var userIdGuid))
            return null;
        return userIdGuid;

    private string? GetIpAddress()
    {
        var forwardedFor = HttpContext.Request.Headers["X-Forwarded-For"].FirstOrDefault();
        if (!string.IsNullOrEmpty(forwardedFor))
            return forwardedFor.Split(',').First().Trim();

        return HttpContext.Connection.RemoteIpAddress?.ToString();
    }
