# Sub-Module 4.1: Dashboards & Workload Tracking

## Functional Requirements Covered

| FR ID | Requirement Name | Description | Priority |
|-------|------------------|-------------|----------|
| FR-038 | Dashboard Metrics View | The system shall display total active tasks, workload balances across employees/departments, and overdue task count. Dashboard filters shall function correctly. Only Coordinators and the Manager shall have access. | High |
| FR-039 | Employee Availability for Assignment | Employees flagged as Offline or On Leave shall appear disabled in task assignment dropdowns. The system shall re-validate assignee availability at the moment of submission. Only Active employees shall be assignable. | High |

## 1. High-Level Pseudocode

### What We're Building

We need to create a system where:
1. Coordinators and Managers can view a dashboard showing total active tasks, workload balance per employee/department, and overdue task count
2. Dashboard data can be filtered by date range, employee, department, and task status
3. Dashboard data reflects current task records at all times (read-only, no writes)
4. When creating or assigning tasks, employees who are Offline or On Leave are shown as unavailable
5. The system re-validates an assignee's availability at the moment of task submission
6. Only employees with Active availability status can be assigned to tasks

### Step-by-Step Logic

```
STEP 1: Create AvailabilityStatus Enum
├── Active → employee is available for assignment
├── Offline → employee is not available (e.g., not logged in / system-marked)
└── OnLeave → employee is on approved leave

STEP 2: Update User Model
├── Add AvailabilityStatus property (default = Active)
└── Existing fields remain unchanged

STEP 3: Create Dashboard DTOs
├── DashboardMetricsDTO → total active tasks, overdue count, workload list
├── WorkloadItemDTO → employee/department name, active task count, overdue count
```

## 2. High-Level Explanation of Concepts

### Concept 1: Dashboard Metrics Aggregation (What it is)

**Dashboard Metrics Aggregation** is the process of querying the database to calculate summary statistics (counts, averages, groupings) from existing task and user records. The dashboard does NOT store its own data — it computes everything on-the-fly from the Tasks, TaskAssignments, and Users tables.

**Why we use it:**
- Real-time accuracy: metrics always reflect the latest task records
- No data duplication: no separate "dashboard data" table to maintain
- Simplicity: one source of truth (the task records)

**How it works:**
```
1. Coordinator/Manager requests dashboard data (GET /api/dashboard/metrics)
2. Backend queries the Tasks table:
   - Active tasks = tasks WHERE Status IN (NotStarted, InProgress, DonePendingReview)
   - Overdue tasks = active tasks WHERE Deadline < DateTime.UtcNow
3. Backend queries TaskAssignments + Users:
   - For each employee, count their active tasks
   - Group by department if needed
4. Backend returns the computed metrics as a JSON response
5. Frontend renders charts/numbers from this data

EXAMPLE:
- Total Active Tasks: 45
- Overdue Tasks: 3
- Workload:
  ├── John Doe: 8 active tasks (1 overdue)
  ├── Jane Smith: 5 active tasks (0 overdue)
  └── Dispatch Dept: 20 active tasks (2 overdue)
```

**Alternatives:**
- **Pre-computed/cached metrics**: Store metrics in a separate table, update periodically. Faster but can be stale.
- **SignalR push**: Server pushes updates to clients. More complex but enables real-time auto-refresh.
- **Materialized views**: Database-level aggregation. Overkill for this scale.

**Common Mistakes:**
- Including Completed or Cancelled tasks in "active" counts
- Not filtering by the user's role (Coordinators should only see their department)
- Forgetting to exclude On Hold tasks from overdue counts (or including them — depends on business rules)
- Not applying date range filters correctly

---

### Concept 2: Workload Balance Calculation (What it is)

**Workload Balance Calculation** determines how many active tasks each employee (or department) currently has. This helps Coordinators distribute work evenly and identify overloaded employees.

**Why we use it:**
- Fair distribution: prevents one employee from having 20 tasks while another has 2
- Capacity planning: Coordinators can see who has bandwidth for new tasks
- Overdue prevention: overloaded employees are more likely to miss deadlines

**How it works:**
```
PER-EMPLOYEE WORKLOAD:
1. Query all TaskAssignment records
2. Join with Tasks WHERE Status IN (NotStarted, InProgress, DonePendingReview)
3. Group by AssignedUserId
4. Count tasks per user
5. Optionally include overdue count per user

PER-DEPARTMENT WORKLOAD:
1. Same as above, but group by user.DepartmentId instead
2. Sum all active tasks for users in each department

EXAMPLE OUTPUT:
[
  { employeeName: "John Doe", activeTasks: 8, overdueTasks: 1, department: "Dispatch" },
  { employeeName: "Jane Smith", activeTasks: 3, overdueTasks: 0, department: "Dispatch" },
  { employeeName: "Bob Lee", activeTasks: 12, overdueTasks: 2, department: "Encoding" }
]
```

**Alternatives:**
- **Weighted workload**: Assign different weights to tasks based on priority. More accurate but more complex.
- **Time-based workload**: Calculate hours estimated per task. Requires time estimation fields.
- **Round-robin auto-assignment**: System auto-assigns to least-loaded employee. Not required by FR.

**Common Mistakes:**
- Counting Completed/Cancelled tasks as "active workload"
- Not joining through TaskAssignment (tasks can have multiple assignees)
- Forgetting to filter by department for Coordinator view
- Including deactivated users in workload calculations

### Concept 3: Employee Availability Status (What it is)

**Employee Availability Status** is a flag on each user record that indicates whether the employee is currently available to be assigned new tasks. It has three states: Active (available), Offline (not available), and OnLeave (on approved leave).

**Why we use it:**
- Prevents assigning tasks to employees who can't work on them
- Gives Coordinators visibility into who is available before creating tasks
- Re-validation at submission time prevents race conditions (status changed after dropdown loaded)

**How it works:**
```
THREE STATES:
├── Active → employee is available, can be assigned tasks
├── Offline → employee is temporarily unavailable
└── OnLeave → employee is on approved leave

FLOW:
1. Coordinator opens task creation form
2. Frontend calls GET /api/dashboard/employee-availability
3. Backend returns list of employees with their availability status
4. Frontend renders dropdown:
   - Active employees → selectable (normal text)
   - Offline/OnLeave employees → disabled (grayed out, non-selectable)
5. Coordinator selects an Active employee
6. Coordinator submits the form (POST /api/tasks)
7. Backend RE-VALIDATES: Is the selected employee still Active?
   ├── Yes → proceed with task creation
   └── No → return error: "Selected employee is currently unavailable"

RE-VALIDATION IS CRITICAL:
- Between loading the dropdown and submitting, an employee's status could change
- Example: Coordinator loads dropdown (John is Active), goes to lunch,
  comes back and submits (John is now OnLeave)
- Without re-validation, the task would be assigned to someone on leave
```

**Alternatives:**
- **Real-time WebSocket**: Push status changes to frontend instantly. More complex.
- **No re-validation**: Trust the dropdown state. Risk of assigning to unavailable employees.
- **Automatic status based on login**: Set Offline when not logged in. Doesn't cover OnLeave.

**Common Mistakes:**
- Not re-validating at submission time (race condition)
- Forgetting to include availability status in the assignable users response
- Not distinguishing between Offline and OnLeave (they have different meanings)
- Allowing Deactivated users to appear (they should be completely excluded, not just disabled)

### Concept 4: Overdue Task Detection (What it is)

**Overdue Task Detection** identifies tasks whose deadline has passed but are not yet Completed or Cancelled. These tasks require immediate attention and are flagged on the dashboard.

**Why we use it:**
- Visibility: Coordinators/Managers need to know which tasks are behind schedule
- Escalation: overdue tasks may need reassignment or deadline revision
- KPI tracking: overdue counts feed into performance metrics

**How it works:**
```
OVERDUE = Task WHERE:
  ├── Deadline < DateTime.UtcNow (deadline has passed)
  ├── Status != Completed (not finished)
  └── Status != Cancelled (not cancelled)

NOTE: OnHold tasks may or may not be considered overdue depending on business rules.
For this implementation, OnHold tasks ARE counted as overdue if their deadline has passed.

EXAMPLE:
Current time: 2026-07-13 19:00 UTC

Task A: Deadline = 2026-07-12, Status = InProgress → OVERDUE
Task B: Deadline = 2026-07-14, Status = InProgress → NOT overdue (deadline in future)
Task C: Deadline = 2026-07-10, Status = Completed → NOT overdue (already done)
Task D: Deadline = 2026-07-11, Status = Cancelled → NOT overdue (cancelled)
Task E: Deadline = 2026-07-12, Status = OnHold → OVERDUE (deadline passed, not completed/cancelled)
```

**Common Mistakes:**
- Using CreatedAt instead of Deadline for overdue calculation
- Not excluding Completed and Cancelled tasks
- Using local time instead of UTC (timezone issues)
- Not considering RevisedDeadline if the task had its deadline revised

**File: `backend/Modules/TaskManagement/DashboardService.cs`**

```csharp
using Microsoft.EntityFrameworkCore;
using Backend.Data;
using Backend.Models;
using Backend.Models.DTOs;
using Backend.Models.Enums;

namespace Backend.Modules.TaskManagement;

public class DashboardService : IDashboardService
{
    private readonly AppDbContext _db;

    public DashboardService(AppDbContext db)
    {
        _db = db;
    }

    public async Task<ApiResponseDTO<DashboardMetricsDTO>> GetDashboardMetricsAsync(
        Guid requestUserId,
        UserRole requestUserRole,
        Guid? requestUserDepartmentId,
        DashboardFilterDTO? filters = null)
    {
        var activeStatuses = new[]
        {
            TaskStatus.NotStarted,
            TaskStatus.InProgress,
            TaskStatus.DonePendingReview
        };

        var query = _db.Tasks
            .Include(t => t.Assignments)
                .ThenInclude(a => a.AssignedUser)
            .AsQueryable();

        if (requestUserRole == UserRole.Coordinator && requestUserDepartmentId.HasValue)
            query = query.Where(t => t.AssignedDepartmentId == requestUserDepartmentId.Value);

        if (filters != null)
        {
            if (filters.DateRangeStart.HasValue)
                query = query.Where(t => t.CreatedAt >= filters.DateRangeStart.Value.ToUniversalTime());

            if (filters.DateRangeEnd.HasValue)
                query = query.Where(t => t.CreatedAt <= filters.DateRangeEnd.Value.ToUniversalTime().Date.AddDays(1));

            if (filters.DepartmentId.HasValue)
                query = query.Where(t => t.AssignedDepartmentId == filters.DepartmentId.Value);

            if (filters.Status.HasValue)
                query = query.Where(t => t.Status == filters.Status.Value);

            if (filters.EmployeeId.HasValue)
                query = query.Where(t => t.Assignments.Any(a => a.AssignedUserId == filters.EmployeeId.Value));
        }

        var allTasks = await query.ToListAsync();

        var activeTasks = allTasks.Where(t => activeStatuses.Contains(t.Status)).ToList();
        var now = DateTime.UtcNow;
        var overdueTasks = activeTasks.Where(t => t.Deadline < now).ToList();

        var employeeWorkload = activeTasks
            .SelectMany(t => t.Assignments.Select(a => new { a.AssignedUserId, Task = t }))
            .GroupBy(x => x.AssignedUserId)
            .Select(g =>
            {
                var firstAssignment = g.First();
                var user = firstAssignment.Task.Assignments
                    .FirstOrDefault(a => a.AssignedUserId == g.Key)?.AssignedUser;

                return new WorkloadItemDTO
                {
                    EmployeeId = g.Key,
                    EmployeeName = user is not null
                        ? $"{user.FirstName} {user.LastName}".Trim()
                        : "Unknown",
                    EmployeeNumber = user?.EmployeeNumber ?? "",
                    Role = user?.Role.ToString() ?? "",
                    Department = user?.Department?.Name ?? "",
                    ActiveTaskCount = g.Count(),
                    OverdueTaskCount = g.Count(x => x.Task.Deadline < now),
                    AvailabilityStatus = new AvailabilityStatusDTO
                    {
                        Status = user?.AvailabilityStatus.ToString() ?? "Unknown",
                        IsAvailable = user?.AvailabilityStatus == AvailabilityStatus.Active
                    }
                };
            })
            .OrderByDescending(w => w.ActiveTaskCount)
            .ToList();

        var departmentWorkload = activeTasks
            .Where(t => t.AssignedDepartmentId.HasValue)
            .GroupBy(t => t.AssignedDepartmentId!.Value)
            .Select(g => new DepartmentWorkloadDTO
            {
                DepartmentId = g.Key,
                DepartmentName = g.First().AssignedDepartment?.Name ?? "Unknown",
                TotalActiveTasks = g.Count(),
                TotalOverdueTasks = g.Count(t => t.Deadline < now),
                EmployeeCount = g.SelectMany(t => t.Assignments)
                    .Select(a => a.AssignedUserId)
                    .Distinct()
                    .Count()
            })
            .OrderByDescending(d => d.TotalActiveTasks)
            .ToList();

        var completedToday = allTasks
            .Count(t => t.Status == TaskStatus.Completed
                && t.UpdatedAt.HasValue
                && t.UpdatedAt.Value.Date == now.Date);

        var metrics = new DashboardMetricsDTO
        {
            TotalActiveTasks = activeTasks.Count,
            OverdueTaskCount = overdueTasks.Count,
            NotStartedCount = activeTasks.Count(t => t.Status == TaskStatus.NotStarted),
            InProgressCount = activeTasks.Count(t => t.Status == TaskStatus.InProgress),
            DonePendingReviewCount = activeTasks.Count(t => t.Status == TaskStatus.DonePendingReview),
            OnHoldCount = allTasks.Count(t => t.Status == TaskStatus.OnHold),
            CompletedTodayCount = completedToday,
            EmployeeWorkload = employeeWorkload,
            DepartmentWorkload = departmentWorkload
        };

        return ApiResponseDTO<DashboardMetricsDTO>.Success(metrics);
    }

    public async Task<ApiResponseDTO<List<DepartmentWorkloadDTO>>> GetWorkloadByDepartmentAsync(
        Guid requestUserId,
        UserRole requestUserRole,
        Guid? requestUserDepartmentId,
        DashboardFilterDTO? filters = null)
    {
        var activeStatuses = new[]
        {
            TaskStatus.NotStarted,
            TaskStatus.InProgress,
            TaskStatus.DonePendingReview
        };

        var query = _db.Tasks
            .Include(t => t.AssignedDepartment)
            .Include(t => t.Assignments)
            .AsQueryable();

        if (requestUserRole == UserRole.Coordinator && requestUserDepartmentId.HasValue)
            query = query.Where(t => t.AssignedDepartmentId == requestUserDepartmentId.Value);

        if (filters != null)
        {
            if (filters.DateRangeStart.HasValue)
                query = query.Where(t => t.CreatedAt >= filters.DateRangeStart.Value.ToUniversalTime());

            if (filters.DateRangeEnd.HasValue)
                query = query.Where(t => t.CreatedAt <= filters.DateRangeEnd.Value.ToUniversalTime().Date.AddDays(1));

            if (filters.DepartmentId.HasValue)
                query = query.Where(t => t.AssignedDepartmentId == filters.DepartmentId.Value);
        }

        var tasks = await query.ToListAsync();
        var activeTasks = tasks.Where(t => activeStatuses.Contains(t.Status)).ToList();
        var now = DateTime.UtcNow;

        var departmentWorkload = activeTasks
            .Where(t => t.AssignedDepartmentId.HasValue)
            .GroupBy(t => t.AssignedDepartmentId!.Value)
            .Select(g => new DepartmentWorkloadDTO
            {
                DepartmentId = g.Key,
                DepartmentName = g.First().AssignedDepartment?.Name ?? "Unknown",
                TotalActiveTasks = g.Count(),
                TotalOverdueTasks = g.Count(t => t.Deadline < now),
                EmployeeCount = g.SelectMany(t => t.Assignments)
                    .Select(a => a.AssignedUserId)
                    .Distinct()
                    .Count()
            })
            .OrderByDescending(d => d.TotalActiveTasks)
            .ToList();

        return ApiResponseDTO<List<DepartmentWorkloadDTO>>.Success(departmentWorkload);
    }

    public async Task<ApiResponseDTO<List<EmployeeAvailabilityResponseDTO>>> GetEmployeeAvailabilityAsync(
        Guid? departmentId = null)
    {
        var query = _db.Users
            .Include(u => u.Department)
            .Where(u => u.IsActive && !u.IsDeactivated)
            .AsQueryable();

        if (departmentId.HasValue)
            query = query.Where(u => u.DepartmentId == departmentId.Value);

        var users = await query
            .OrderBy(u => u.LastName)
            .ThenBy(u => u.FirstName)
            .ToListAsync();

        var result = users.Select(u => new EmployeeAvailabilityResponseDTO
        {
            UserId = u.Id,
            FullName = $"{u.FirstName} {u.MiddleName} {u.LastName} {u.Suffix}"
                .Replace("  ", " ").Trim(),
            EmployeeNumber = u.EmployeeNumber,
            Role = u.Role.ToString(),
            Department = u.Department?.Name ?? "",
            AvailabilityStatus = u.AvailabilityStatus,
            IsAvailable = u.AvailabilityStatus == AvailabilityStatus.Active
        }).ToList();

        return ApiResponseDTO<List<EmployeeAvailabilityResponseDTO>>.Success(result);
    }

    public async Task<ApiResponseDTO<bool>> ValidateAssigneeAvailabilityAsync(Guid userId)
    {
        var user = await _db.Users.FindAsync(userId);
        if (user is null)
            return ApiResponseDTO<bool>.Failure("Employee not found");

        if (!user.IsActive || user.IsDeactivated)
            return ApiResponseDTO<bool>.Failure("Employee is deactivated");

        if (user.AvailabilityStatus != AvailabilityStatus.Active)
            return ApiResponseDTO<bool>.Failure(
                $"Selected employee is currently unavailable ({user.AvailabilityStatus}). Please choose another employee.");

        return ApiResponseDTO<bool>.Success(true);
    }
}
```

```csharp
using System.Security.Claims;
using Microsoft.AspNetCore.Authorization;
using Microsoft.AspNetCore.Mvc;
using Backend.Data;
using Backend.Models;
using Backend.Models.DTOs;
using Backend.Models.Enums;
using Backend.Modules.TaskManagement;
using Backend.Modules.RoleBasedAccessControl;

namespace Backend.Controllers;

[ApiController]
[Route("api/[controller]")]
[Authorize]
public class DashboardController : ControllerBase
{
    private readonly IDashboardService _dashboardService;
    private readonly AppDbContext _db;

    public DashboardController(IDashboardService dashboardService, AppDbContext db)
    {
        _dashboardService = dashboardService;
        _db = db;
    }

    [HttpGet("metrics")]
    [Authorize(Policy = AuthorizationPolicies.CoordinatorAndAbove)]
    public async Task<IActionResult> GetMetrics(
        [FromQuery] DateTime? dateRangeStart = null,
        [FromQuery] DateTime? dateRangeEnd = null,
        [FromQuery] Guid? employeeId = null,
        [FromQuery] Guid? departmentId = null,
        [FromQuery] TaskStatus? status = null)
    {
        var userId = User.FindFirst(ClaimTypes.NameIdentifier)?.Value;
        var userRoleStr = User.FindFirst(ClaimTypes.Role)?.Value;

        if (string.IsNullOrEmpty(userId) || !Guid.TryParse(userId, out var requestUserId))
            return Unauthorized(ApiResponseDTO<object>.Failure("Invalid user token"));

        if (!Enum.TryParse<UserRole>(userRoleStr, true, out var requestUserRole))
            return Unauthorized(ApiResponseDTO<object>.Failure("Invalid role"));

        Guid? requestUserDepartmentId = null;
        if (requestUserRole == UserRole.Coordinator)
        {
            var user = await _db.Users.FindAsync(requestUserId);
            requestUserDepartmentId = user?.DepartmentId;
        }

        var filters = new DashboardFilterDTO
        {
```

- Only validates when `dto.AssignedUserIds != null` (assignee changes are requested)
