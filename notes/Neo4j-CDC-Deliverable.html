CDC Deliverable — Data Extraction Pipeline

Capstone 2 — STARS: Suitability Task Assignment and Recommendation System

Requirement: "Working script that reads from Capstone 1's database (via Read-Replica or direct SELECT) and writes sample data to the new Columnar DB."

This document demonstrates our CDC-based data extraction pipeline. Instead of a traditional script that issues direct SELECT queries, our pipeline uses Change Data Capture (CDC) via PostgreSQL logical replication, Debezium, Kafka, and a custom .NET processor to continuously extract data from the operational database and write transformed/derived data to Neo4j.

Architecture Overview

PostgreSQL (Source DB) │ wal_level=logical | publication=stars_cdc ▼ Debezium (CDC Connector, port 8083) │ Reads WAL → publishes JSON to Kafka ▼ Kafka (Message Broker, port 9092) │ Topics: stars.public.Users, Tasks, TaskAssignments, Recommendations, Departments ▼ CDC Processor (.NET 9 Worker) │ Every 10 min: consumes Kafka → computes derived insights ▼ Neo4j (Graph Database, ports 7474/7687) │ Employee, Task, Department nodes with derived properties

Source Code

1. PostgreSQL Configuration

File: postgres-init.sql

CREATE PUBLICATION stars_cdc FOR ALL TABLES;

This SQL runs on first database initialization. It creates a publication that broadcasts all table changes for Debezium to consume.

File: docker-compose.yml (db service)

db: image: postgres:16-alpine command: - "postgres" - "-c" - "wal_level=logical" - "-c" - "max_replication_slots=5" - "-c" - "max_wal_senders=5" volumes: - ./postgres-init.sql:/docker-entrypoint-initdb.d/init.sql

Explanation: wal_level=logical enables the WAL to store row-level before/after images. max_replication_slots=5 allows Debezium to create a bookmark in the WAL. max_wal_senders=5 allows Debezium to connect and stream changes.

2. Debezium Connector Configuration

Registered via REST API at POST http://localhost:8083/connectors

{ "name": "stars-postgres-connector", "config": { "connector.class": "io.debezium.connector.postgresql.PostgresConnector", "database.hostname": "db", "database.port": "5432", "database.user": "postgres", "database.password": "postgres", "database.dbname": "backend_db", "topic.prefix": "stars", "table.include.list": "public.*", "plugin.name": "pgoutput", "slot.name": "stars_cdc_slot", "publication.name": "stars_cdc" } }

Explanation: This tells Debezium to connect to PostgreSQL, subscribe to the stars_cdc publication via replication slot stars_cdc_slot, and publish every row change to a Kafka topic prefixed with stars.

3. CDC Processor — Program.cs

File: cdc-processor/Program.cs

var builder = Host.CreateApplicationBuilder(args); builder.Services.Configure<KafkaOptions>( builder.Configuration.GetSection("Kafka")); builder.Services.Configure<Neo4jOptions>( builder.Configuration.GetSection("Neo4j")); builder.Services.AddSingleton<KafkaCdcConsumer>(); builder.Services.AddSingleton<Neo4jDataWriter>(); builder.Services.AddHostedService<CdcWorker>(); var host = builder.Build(); host.Run();

Explanation: The entry point configures dependency injection for the Kafka consumer, Neo4j writer, and the background worker.

4. CDC Processor — CdcWorker.cs (The Background Loop)

File: cdc-processor/Workers/CdcWorker.cs

public class CdcWorker : BackgroundService { protected override async Task ExecuteAsync(CancellationToken stoppingToken) { _logger.LogInformation("CDC Processor started. Sync interval: {Interval} minutes", _syncIntervalMinutes); while (!stoppingToken.IsCancellationRequested) { _logger.LogInformation("Starting CDC sync cycle at {Time}", DateTime.UtcNow); var events = _consumer.ConsumeAllAvailable(); if (events.Count > 0) { await _writer.ProcessAndWriteAsync(events); _logger.LogInformation("CDC sync cycle completed: {Count} events processed", events.Count); } await Task.Delay(TimeSpan.FromMinutes(_syncIntervalMinutes), stoppingToken); } } }

Explanation: Every 10 minutes, the worker calls ConsumeAllAvailable() to read new CDC events from Kafka. If events exist, it passes them to ProcessAndWriteAsync() which computes derived insights and writes them to Neo4j.

5. CDC Processor — KafkaCdcConsumer.cs (Reading from Source DB via CDC)

File: cdc-processor/Services/KafkaCdcConsumer.cs

public List<CdcPayload> ConsumeAllAvailable() { // 1. List available Kafka topics (stars.public.*) var availableTopics = GetAvailableTopics(); var topicsToRead = _options.Topics .Where(t => availableTopics.Contains(t)).ToList(); // 2. Create Kafka consumer with Earliest offset var config = new ConsumerConfig { BootstrapServers = _options.BootstrapServers, GroupId = _options.GroupId, AutoOffsetReset = AutoOffsetReset.Earliest, EnableAutoCommit = false, }; using var consumer = new ConsumerBuilder<string, string>(config).Build(); consumer.Subscribe(topicsToRead); // 3. Poll for up to 30 seconds while (DateTime.UtcNow - started < totalWait) { var result = consumer.Consume(TimeSpan.FromSeconds(5)); if (result == null || result.IsPartitionEOF) continue; // 4. Deserialize Debezium JSON envelope var envelope = JsonSerializer.Deserialize<DebeziumEnvelope>(result.Message.Value); if (envelope?.Payload != null) { envelope.Payload.Source ??= new CdcSource(); envelope.Payload.Source.Table = result.Topic; events.Add(envelope.Payload); } } return events; }

Explanation: This is the "read script." Instead of issuing SQL SELECT queries, it consumes CDC events that Debezium published to Kafka. Each event contains the full row data (after), previous values (before), and metadata (table, operation type, LSN).

6. CDC Processor — Neo4jDataWriter.cs (Writing to Neo4j)

File: cdc-processor/Services/Neo4jDataWriter.cs

Derived Insights Calculation:

private DerivedData CalculateDerivedInsights(List<CdcPayload> events) { // Group events by table foreach (var evt in events) { var tableName = ExtractTableName(evt.Source?.Table ?? ""); var data = evt.After ?? evt.Before; if (data == null) continue; switch (tableName) { case "Users": latestUsers[userId] = data; break; case "Tasks": latestTasks[taskId] = data; break; case "TaskAssignments": allAssignments.Add(data); break; case "Recommendations": allRecommendations.Add(data); break; case "Departments": latestDepartments[deptId] = data; break; } } // Compute workload: count active (status 0/1/2) task assignments per employee var taskStatusInProgress = new HashSet<string> { "0", "1", "2" }; foreach (var assignment in allAssignments) { if (taskStatusInProgress.Contains(status)) counts.active++; } // Compute recommendation scores: ratio per category foreach (var rec in allRecommendations) { switch (category) { case "Timeliness": counts.timeliness++; break; case "WorkQuality": counts.quality++; break; case "Communication": counts.communication++; break; } } // Build EmployeeData with derived properties foreach (var (uId, user) in latestUsers) { result.Employees.Add(new EmployeeData { Workload = taskCounts.active, CompletedRoutineTasks = taskCounts.routineCompleted, CompletedSpecialTasks = taskCounts.specialCompleted, AvgTimelinessScore = timeliness / total, AvgWorkQualityScore = quality / total, AvgCommunicationScore = communication / total, }); } }

Writing to Neo4j via Cypher MERGE:

// Write Employee nodes with derived properties await tx.RunAsync(@" MERGE (e:Employee {id: $id}) SET e.employeeNumber = $employeeNumber, e.firstName = $firstName, e.lastName = $lastName, e.role = $role, e.availabilityStatus = $availabilityStatus, e.workload = $workload, e.completedRoutineTasks = $completedRoutineTasks, e.completedSpecialTasks = $completedSpecialTasks, e.avgTimelinessScore = $avgTimelinessScore, e.avgWorkQualityScore = $avgWorkQualityScore, e.avgCommunicationScore = $avgCommunicationScore", new { id, employeeNumber, firstName, lastName, role, availabilityStatus, workload, completedRoutineTasks, completedSpecialTasks, avgTimelinessScore, avgWorkQualityScore, avgCommunicationScore }); // Create BELONGS_TO relationship await tx.RunAsync( "MATCH (e:Employee {id: $empId}), (d:Department {id: $deptId}) " + "MERGE (e)-[:BELONGS_TO]->(d)", new { empId, deptId }); // Create ASSIGNED_TO relationship await tx.RunAsync( "MATCH (e:Employee {id: $empId}), (t:Task {id: $taskId}) " + "MERGE (e)-[:ASSIGNED_TO {assignedAt: $assignedAt}]->(t)", new { empId, taskId, assignedAt });

Explanation: The writer extracts the latest state of each entity from the CDC events, computes derived aggregates (workload, experience counts, recommendation scores), then writes them to Neo4j using Cypher MERGE statements (create if not exists, update if exists). This is the equivalent of "writing sample data to the new Columnar DB."

8. Suitability Query (Neo4j — Target DB Read)

File: backend/Modules/TaskManagement/SuitabilityService.cs

var result = await session.ExecuteReadAsync(async tx => { var cursor = await tx.RunAsync(@" MATCH (d:Department {id: $departmentId}) MATCH (e:Employee)-[:BELONGS_TO]->(d) WHERE e.availabilityStatus = '0' AND e.role IN $eligibleRoleIds WITH e, 1.0 - (e.workload * 1.0 / $maxWorkload) AS workloadFactor, CASE WHEN $classification = 'RoutineDailyTask' THEN e.completedRoutineTasks * 1.0 / $maxXP ELSE e.completedSpecialTasks * 1.0 / $maxXP END AS experienceFactor, (e.avgTimelinessScore + e.avgWorkQualityScore + e.avgCommunicationScore) / 3.0 AS recScore RETURN e.employeeNumber, e.firstName + ' ' + e.lastName AS fullName, e.workload, (0.35 * workloadFactor + 0.25 * experienceFactor + 0.40 * recScore) AS suitabilityScore ORDER BY suitabilityScore DESC LIMIT 5 ", new { departmentId, eligibleRoleIds, classification, maxWorkload = 10, maxXP = 20 }); });

Explanation: This Cypher query traverses the Neo4j graph from Department → Employee via BELONGS_TO, filters by availability and role, then computes a weighted suitability score based on workload (35%), experience (25%), and recommendation history (40%). This is exposed via GET /api/tasks/{taskId}/suitability.

How to Run the CDC Script

  1. Start everything: docker compose up -d
  2. Verify Debezium connector is running: curl http://localhost:8083/connectors/stars-postgres-connector/status
  3. Make changes in PostgreSQL (e.g., create a task via the STARS frontend or API)
  4. Watch CDC events appear in Kafka: Open http://localhost:8081
  5. Trigger immediate CDC Processor sync: docker compose restart cdc-processor
  6. Verify data reached Neo4j: Open http://localhost:7474 (neo4j/starslab!) and run: MATCH (n) RETURN n LIMIT 25
  7. Query suitability: GET /api/tasks/{taskId}/suitability (requires JWT token)
