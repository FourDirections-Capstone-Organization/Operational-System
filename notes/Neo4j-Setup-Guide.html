1. Should I download Neo4j? (Like PostgreSQL + pgAdmin?)

Short answer: Yes, but differently from PostgreSQL.

PostgreSQL gives you a database server (the engine) and pgAdmin (a GUI browser to run SQL, view tables, etc.). Neo4j works similarly:

ComponentPostgreSQL EquivalentNeo4j Equivalent
Database EnginePostgreSQL server (psql)Neo4j server (the graph engine)
GUI BrowserpgAdmin (web UI at port 5433 or standalone)Neo4j Browser (web UI at port 7474 — built-in!)
Connection Port5432 (or custom)7687 (Bolt protocol — for apps) + 7474 (HTTP — for browser)
Query LanguageSQLCypher

Three ways to install Neo4j

Option 1: Neo4j Desktop (Recommended for Learning)

This is the closest equivalent to PostgreSQL + pgAdmin bundled together.

  • Download from: neo4j.com/download
  • Installs like a normal Windows application
  • Comes with a GUI application to manage databases
  • Has its own built-in browser (port 7474)
  • Can manage multiple Neo4j databases (like pgAdmin managing multiple PostgreSQL instances)
  • Includes Neo4j Bloom (visualization tool) for free trial
  • Best for: learning and development on your local machine

→ Go to neo4j.com → Download → Neo4j Desktop → Install like any Windows app

Option 2: Docker (Recommended for STARS)

Best for the project since the rest of STARS already runs in Docker.

  • Single command to run
  • Matches the deployment environment
  • Easily added to docker-compose.yml
  • Neo4j Browser is still available at port 7474
  • No installation — just pulls the image

Command:

docker run --name stars-neo4j ^ -p 7474:7474 -p 7687:7687 ^ -e NEO4J_AUTH=neo4j/starslab! ^ -v neo4j-data:/data ^ neo4j:latest

7474 = Neo4j Browser (web UI), 7687 = Bolt (app connection)

Option 3: Neo4j Server (Enterprise)

Download neo4j-community-*.zip from neo4j.com, unzip, run bin\neo4j console.

This is the raw server without a GUI installer. Only recommended for production or CI environments.

How to access Neo4j Browser (the "pgAdmin" for Neo4j)

  1. Start Neo4j (via Docker, Desktop, or server)
  2. Open your browser and go to http://localhost:7474
  3. Log in with the credentials you set (e.g., username neo4j, password starslab!)
  4. You will see a query editor where you can write Cypher queries
  5. Results are displayed both as tables and as visual graphs (nodes and relationships shown as bubbles and arrows)
Neo4j Browser vs. pgAdmin comparison:
- pgAdmin: connects to PostgreSQL, shows table schemas, runs SQL
- Neo4j Browser: connects to Neo4j, shows node labels and relationship types, runs Cypher, visualizes graphs
- The big difference: Neo4j Browser can draw the graph visually. When you run MATCH (n) RETURN n LIMIT 25, you see bubbles and arrows — not just rows.

Quick Test — Is Neo4j running?

After starting Neo4j, open http://localhost:7474 and run this Cypher query:

RETURN "Hello from Neo4j for STARS!" AS message;

If you see the message returned, Neo4j is working.

2. How to download and install Kafka and RabbitMQ for CDC?

First, let's clarify what each tool does in our architecture:

ToolRole in CDC PipelineWhere it sits
DebeziumConnects to PostgreSQL, reads the WAL (Write-Ahead Log), converts changes to JSON eventsBetween PostgreSQL and the message queue
KafkaA message queue / event streaming platform. Buffers CDC events so the processor can consume them reliablyBetween Debezium and the CDC Processor
RabbitMQAlternative message queue — simpler but less common for CDC at scaleSame position as Kafka (alternative)
Important Clarification: You do NOT need both Kafka AND RabbitMQ. They are alternatives. We recommend Kafka because Debezium has first-class Kafka support. RabbitMQ requires a separate adapter (Debezium's Kafka -> RabbitMQ bridge). We cover both below so you can choose.

Option A: Kafka + Debezium (Recommended)

What is Kafka?

Kafka is a distributed event streaming platform. Think of it as a highly reliable bulletin board:

  • Producers (Debezium) post messages to a topic (like stars.cdc)
  • Consumers (CDC Processor) read messages from the topic
  • Messages persist for a configurable time even after being consumed
  • If the CDC Processor crashes, events are not lost — it resumes from where it left off

Installing Kafka — The Modern Way (KRaft, no ZooKeeper)

Kafka traditionally required ZooKeeper to manage the cluster. Since Kafka 3.5+, it can run with KRaft (Kafka Raft) — no ZooKeeper needed. We use KRaft for simplicity.

Step 1: Run Kafka in Docker

docker run --name stars-kafka ^ -p 9092:9092 ^ -e KAFKA_PROCESS_ROLES=broker,controller ^ -e KAFKA_NODE_ID=1 ^ -e KAFKA_CONTROLLER_QUORUM_VOTERS=1@localhost:9093 ^ -e KAFKA_LISTENERS=PLAINTEXT://0.0.0.0:9092,CONTROLLER://0.0.0.0:9093 ^ -e KAFKA_ADVERTISED_LISTENERS=PLAINTEXT://localhost:9092 ^ -e KAFKA_LISTENER_SECURITY_PROTOCOL_MAP=PLAINTEXT:PLAINTEXT,CONTROLLER:PLAINTEXT ^ -e KAFKA_CONTROLLER_LISTENER_NAMES=CONTROLLER ^ -e KAFKA_LOG_DIRS=/var/lib/kafka/data ^ -e CLUSTER_ID=stars-cdc-cluster-001 ^ -v kafka-data:/var/lib/kafka/data ^ apache/kafka:latest

What each setting does:

SettingPurpose
KAFKA_PROCESS_ROLES=broker,controllerSingle-node mode: this one container acts as both the broker (stores messages) and the controller (manages the cluster). Equivalent to running PostgreSQL's single instance.
KAFKA_NODE_ID=1A unique ID for this node. Since we only have one, it's 1.
KAFKA_ADVERTISED_LISTENERS=PLAINTEXT://localhost:9092Tells clients (Debezium, CDC Processor) how to reach Kafka. Must match the hostname the client uses.
CLUSTER_ID=stars-cdc-cluster-001Unique cluster ID for KRaft mode. Can be any unique string.
-p 9092:9092Port 9092 is the standard Kafka port — like port 5432 for PostgreSQL.

Step 2: Run Debezium (Kafka Connect)

Debezium is packaged as a Kafka Connect plugin. Kafka Connect runs as a separate service and uses Kafka to store configuration and offsets.

docker run --name stars-debezium ^ --link stars-kafka ^ -p 8083:8083 ^ -e BOOTSTRAP_SERVERS=stars-kafka:9092 ^ -e GROUP_ID=stars-cdc-connect ^ -e CONFIG_STORAGE_TOPIC=stars-connect-configs ^ -e OFFSET_STORAGE_TOPIC=stars-connect-offsets ^ -e STATUS_STORAGE_TOPIC=stars-connect-statuses ^ debezium/connect:latest

What each setting does:

SettingPurpose
BOOTSTRAP_SERVERS=stars-kafka:9092Where to find Kafka. The --link flag makes the hostname stars-kafka resolvable.
GROUP_ID=stars-cdc-connectKafka Connect cluster group ID. If you run multiple Connect workers, they share this ID.
CONFIG_STORAGE_TOPIC, OFFSET_STORAGE_TOPIC, STATUS_STORAGE_TOPICKafka topics where Kafka Connect stores its own metadata. Debezium uses these to track which WAL positions it has read (so it can resume after a restart).
-p 8083:8083The Kafka Connect REST API port. You send HTTP requests here to configure Debezium connectors.
Link vs. Network: The --link flag works for local testing in Docker. For production, use a Docker network (docker network create stars-net) and attach all containers to it. If using Docker Compose (recommended, see section below), services automatically discover each other.

Step 3: Configure the Debezium PostgreSQL Connector

Once Kafka Connect is running, you register a PostgreSQL connector by sending a POST request to its REST API:

curl -X POST http://localhost:8083/connectors ^ -H "Content-Type: application/json" ^ -d "{ \"name\": \"stars-postgres-connector\", \"config\": { \"connector.class\": \"io.debezium.connector.postgresql.PostgresConnector\", \"database.hostname\": \"stars-postgres\", \"database.port\": \"5432\", \"database.user\": \"postgres\", \"database.password\": \"postgres\", \"database.dbname\": \"stars_db\", \"database.server.name\": \"stars\", \"table.include.list\": \"public.Tasks,public.TaskAssignments,public.Users,public.Recommendations,public.Departments\", \"plugin.name\": \"pgoutput\", \"slot.name\": \"stars_cdc_slot\", \"publication.name\": \"stars_cdc\", \"publication.autocreate.mode\": \"filtered\", \"tombstones.on.delete\": \"false\", \"key.converter\": \"org.apache.kafka.connect.json.JsonConverter\", \"value.converter\": \"org.apache.kafka.connect.json.JsonConverter\" } }"

What this does:

SettingPurpose
database.hostnameHostname of your PostgreSQL server. In Docker Compose, this is the service name (e.g., postgres).
plugin.name=pgoutputThe logical replication output plugin. pgoutput is built into PostgreSQL 16 — no extra installation needed.
slot.nameThe replication slot — PostgreSQL uses this to preserve WAL data until Debezium consumes it.
publication.nameMust match the publication you create in PostgreSQL (or let Debezium auto-create it).
table.include.listWhich tables to capture. Format: schema.TableName.

Step 4: Verify the connector is running

curl http://localhost:8083/connectors/stars-postgres-connector/status

If the response shows "state": "RUNNING", Debezium is successfully capturing changes from PostgreSQL and publishing them to Kafka.

Step 5: View CDC events in Kafka

To inspect the actual JSON events flowing through Kafka, you can run a simple consumer inside the Kafka container:

docker exec -it stars-kafka ^ /opt/kafka/bin/kafka-console-consumer.sh ^ --bootstrap-server localhost:9092 ^ --topic stars.public.Tasks ^ --from-beginning

This will print every CDC event for the Tasks table in real time. Press Ctrl+C to stop.

Option B: RabbitMQ + Debezium (Alternative, Simpler)

What is RabbitMQ?

RabbitMQ is a message broker. It's simpler than Kafka — messages are published to exchanges and routed to queues. It's easier to set up but less suited for very high-volume CDC.

FeatureKafkaRabbitMQ
Message retentionPersistent (configurable days/weeks)Ephemeral (deleted after consumed, unless configured)
Event replayYes — can rewind and reprocessNo — once consumed, gone (unless using quorum queues)
Performance at scale100k+ messages/sec~50k messages/sec (still plenty for CDC)
Debezium supportNative (comes built-in)Needs extra adapter (Debezium + Kafka -> RabbitMQ bridge)
Setup complexityModerate (Kafka + Kafka Connect)Simple (RabbitMQ + consumer)

Installing RabbitMQ

Run RabbitMQ in Docker:

docker run --name stars-rabbitmq ^ -p 5672:5672 -p 15672:15672 ^ -e RABBITMQ_DEFAULT_USER=stars ^ -e RABBITMQ_DEFAULT_PASS=starslab! ^ rabbitmq:management

Then open http://localhost:15672 (username: stars, password: starslab!) to see the RabbitMQ management UI.

  • Port 5672: AMQP protocol (app connections) — like Kafka's 9092
  • Port 15672: Management UI (web) — like Neo4j's 7474

Getting CDC events into RabbitMQ

Debezium does not natively publish to RabbitMQ. You have two options:

  1. Debezium + Kafka + RabbitMQ bridge: Debezium publishes to Kafka, then a bridge consumer forwards to RabbitMQ. Adds complexity.
  2. Skip Debezium, use pg_notify + application consumer: PostgreSQL's NOTIFY/LISTEN can push events to a .NET service that publishes to RabbitMQ. Less robust (no WAL-level guarantees).
Recommendation: Use Kafka + Debezium (Option A) instead of RabbitMQ. Debezium is designed for Kafka. RabbitMQ adds an unnecessary extra layer of complexity. Kafka is the industry standard for CDC pipelines.

3. Full Docker Compose — Everything Together

Below is the complete docker-compose.yml that brings up all CDC infrastructure alongside the existing STARS services. Add this to your existing docker-compose.yml at the project root.

version: "3.8" services: # PostgreSQL (existing) postgres: image: postgres:16 environment: POSTGRES_DB: stars_db POSTGRES_USER: postgres POSTGRES_PASSWORD: postgres ports: - "5432:5432" volumes: - postgres-data:/var/lib/postgresql/data # Enable logical replication - ./postgres-init.sql:/docker-entrypoint-initdb.d/init.sql command: - "postgres" - "-c" - "wal_level=logical" - "-c" - "max_replication_slots=5" - "-c" - "max_wal_senders=5" healthcheck: test: ["CMD-SHELL", "pg_isready"] interval: 10s timeout: 5s retries: 5 # Kafka (KRaft mode - no ZooKeeper) kafka: image: apache/kafka:latest ports: - "9092:9092" environment: KAFKA_PROCESS_ROLES: broker,controller KAFKA_NODE_ID: 1 KAFKA_CONTROLLER_QUORUM_VOTERS: 1@localhost:9093 KAFKA_LISTENERS: PLAINTEXT://0.0.0.0:9092,CONTROLLER://0.0.0.0:9093 KAFKA_ADVERTISED_LISTENERS: PLAINTEXT://localhost:9092 KAFKA_LISTENER_SECURITY_PROTOCOL_MAP: PLAINTEXT:PLAINTEXT,CONTROLLER:PLAINTEXT KAFKA_CONTROLLER_LISTENER_NAMES: CONTROLLER KAFKA_LOG_DIRS: /var/lib/kafka/data CLUSTER_ID: stars-cdc-cluster-001 volumes: - kafka-data:/var/lib/kafka/data healthcheck: test: ["CMD-SHELL", "kafka-topics.sh --bootstrap-server localhost:9092 --list"] interval: 15s timeout: 5s retries: 5 # Debezium (Kafka Connect with PostgreSQL connector) debezium: image: debezium/connect:latest ports: - "8083:8083" environment: BOOTSTRAP_SERVERS: kafka:9092 GROUP_ID: stars-cdc-connect CONFIG_STORAGE_TOPIC: stars-connect-configs OFFSET_STORAGE_TOPIC: stars-connect-offsets STATUS_STORAGE_TOPIC: stars-connect-statuses depends_on: kafka: condition: service_healthy postgres: condition: service_healthy # Neo4j neo4j: image: neo4j:latest ports: - "7474:7474" # Neo4j Browser (web UI) - "7687:7687" # Bolt protocol (app connection) environment: NEO4J_AUTH: neo4j/starslab! volumes: - neo4j-data:/data # CDC Processor (.NET Background Service) cdc-processor: build: context: ./cdc-processor dockerfile: Dockerfile environment: KAFKA__BootstrapServers: kafka:9092 KAFKA__GroupId: stars-cdc-processor KAFKA__Topic: stars.cdc NEO4J__Uri: bolt://neo4j:7687 NEO4J__User: neo4j NEO4J__Password: starslab! SyncIntervalMinutes: "10" depends_on: - kafka - neo4j volumes: postgres-data: kafka-data: neo4j-data:

What this Docker Compose file does:

ServicePurpose in the pipeline
postgresModified with wal_level=logical and max_replication_slots=5 to enable CDC. Also runs an init script to create the publication.
kafkaStores CDC event messages. Uses KRaft mode (no ZooKeeper).
debeziumConnects to PostgreSQL, captures row changes, publishes JSON events to Kafka topics.
neo4jGraph database storing derived employee suitability data.
cdc-processorYour custom .NET Background Service that reads from Kafka and writes derived insights to Neo4j.

PostgreSQL Init Script (postgres-init.sql)

Create this file next to your docker-compose.yml to automatically set up the publication when PostgreSQL starts for the first time:

-- Enable logical replication for CDC CREATE PUBLICATION stars_cdc FOR TABLE "Tasks", "TaskAssignments", "Users", "Recommendations", "Departments"; -- Create a user for Debezium with replication privileges -- (Skip if using the default postgres user) -- CREATE ROLE debezium WITH LOGIN REPLICATION PASSWORD 'debezium';

4. Testing the Setup

Once everything is running, follow these steps to confirm the pipeline works end-to-end:

StepActionExpected Result
1. Check Neo4jOpen http://localhost:7474 and log inNeo4j Browser appears. Run RETURN "Neo4j is running" AS message; — shows the message.
2. Check KafkaRun docker exec stars-kafka kafka-topics.sh --bootstrap-server localhost:9092 --listShows topics like stars.public.Tasks, stars.public.Users, etc.
3. Check DebeziumRun curl http://localhost:8083/connectors/stars-postgres-connector/statusReturns {"state": "RUNNING"}
4. Watch CDC eventsMake a change in STARS (e.g., create a task), then watch Kafka: docker exec stars-kafka kafka-console-consumer.sh --bootstrap-server localhost:9092 --topic stars.public.Tasks --from-beginningJSON events appear showing the change with "op": "c" (create) or "op": "u" (update)
5. Check Neo4j dataAfter the CDC processor runs (or manually), query Neo4j: MATCH (e:Employee) RETURN e LIMIT 10Employee nodes appear with derived properties like workload, avgTimelinessScore
6. Run suitability queryExecute the Cypher suitability query from the architecture documentReturns ranked employees with suitability scores
