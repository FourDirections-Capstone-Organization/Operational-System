2. How the CDC Processor Works

PostgreSQL → (WAL) → Debezium → (JSON events) → Kafka → CDC Processor → Neo4j

Each sync cycle (every 10 minutes):

  1. List available topics — query Kafka via AdminClient for topics matching stars.public.*
  2. Subscribe and consume — create a consumer with AutoOffsetReset.Earliest, read all available messages (up to 12 polls × 10s timeout)
  3. Deserialize — parse each message as DebeziumEnvelope, extract the payload containing op, before, after, source
  4. Calculate derived insights — in CalculateDerivedInsights():
    • Group events by table (Users, Tasks, TaskAssignments, Recommendations, Departments)
    • Track latest state per entity (using after values)
    • Count active assignments per employee → workload
    • Count completed tasks by classification → completedRoutineTasks, completedSpecialTasks
    • Count recommendations by category → avgTimelinessScore, avgWorkQualityScore, avgCommunicationScore
    • Track availability status changes → availabilityStatus
  5. Write to Neo4j — execute MERGE statements for each derived entity and relationship
